# 普通四步去重串联与 Markdup 边界回归

日期：2026-09-27。输入 `WES_0.25G.bam`，2,668,351 条记录。
SWLS 单节点、6 MPI ranks、每 rank 64 CPE，memory 输入/输出、BAM level 1。
本轮四个命令各自读写阶段文件，不使用 `dedup-pipeline` 或 `dedup-workflow`。

## 问题与根因

四阶段原先全部正常退出，最终 `stats --basic`（8316948）也能读取全部记录并给出
`is sorted=1`，但 DUP 为 15,694。与历史 SAM 基线及历史 pipeline 输出比较失败，
因此“作业成功、记录数正确、可解析”不足以判定去重正确。

逐条比较**同一个 sorted BAM**的 np=1 与 np=6 输出，遍历全部 2,668,351 条：

- 恰好 1 条记录不同，序号 891,696（从 0 开始），也是 rank 2 的第一条记录。
- QNAME=`SRR7890919.10316987`，tid=15，pos=89,835,468（BAM 从 0 开始）。
- np=1 FLAG=1187，np=6 FLAG=163，只差 `0x400`；去掉 DUP 位后，全部 record
  字节一致，包括 QNAME、坐标、CIGAR、SEQ、QUAL、mate 字段及 AUX。
- `mandatory_fields_fp` 包含 FLAG，因此其差异也可由这一 DUP 位造成，不能据此
  推断 fixmate 的 mate 字段发生损坏。

`MdExtractCandidatesPass()` 在批后处理返回后会清空 candidate/QNAME 容器。
`MdCaptureBoundaryProbe()` 原先只捕获首尾坐标，没有保存这两个容器，导致
`MdBuildOnePassBoundaryPlan()` 获得空候选，却仍设置 `enabled=1`。
主窗口据此关闭了保守的 rank 边界保留策略，某些跨 rank 候选到达时，同键 winner
已被释放，产生依赖 BGZF 分区的漏标。该回调与清空行为在迁移前的 HEAD 中也已存在，
此前固定输入的迁移前后对比没有触发它。

## 修复

- probe context 在回调内用 `swap` 接管 candidate 和 QNAME，一并保留偏移与对应
  字节。extract 返回后再交给边界筛选、owner exchange 和判重，不额外复制 payload。
- 校验 probe 只捕获一个批次，且保留候选数等于提取统计中的 pair+single 数；
  契约不满足时各 rank 一致退出，不能静默启用不完整的预判计划。
- 恢复真实 halo 后，逐候选查询非空表曾使 4.3 增至 0.902196 s。现保存首尾 probe
  的全局 block 范围，对不与其相交的批次跳过预判状态查询和候选过滤；首尾批次仍
  使用原精确 ID 查表，判重键、tie-break 和 MPI owner 规则不变。

修改位于 `apps/mpi/algorithms/markdup/swbam_markdup_mpi.cpp`，保留公共读写流水线。
最终触发输入 `tracked_peak_max=139,051,288 B`，较修复前 139,050,632 B 多 656 B；
`stream_pending_peak_max=12,619,909 B` 不变。它们是工作区估计，不包含完整 I/O 驻留。

## 验证与复现

Sunway 构建、`git diff --check` 通过。最终二进制基于 HEAD `2ac91d3` 加工作区改动，
SHA-256：`d994ce5fb12f1704abc874d33760f60c08c832114e237530c16982d5e4d89695`。

在 `build_sunway_sduhpc` 执行：

```bash
bsub.py swls -q q_share -I -b -J md_halo_fast \
  -N 1 -np 6 -cgsp 64 -share_size 14000 -cache_size 32 \
  -o workflow_smoke_markdup_halo_fast_20260927.log \
  -x LD_LIBRARY_PATH=../ext/htslib-1.20:../ext/libdeflate-1.20/build \
  ./RabbitBAM-MPI@online/guoshi/wzs/code/RabbitBAM/build_sunway_sduhpc \
  markdup -i ../performance_test/workflow_smoke_20260927.sort.bam \
  -o ../performance_test/workflow_smoke_20260927.markdup.halo_fast.bam \
  --compress-level 1 -m 8G --stream -l 300
```

此前三步使用相同资源参数、修复前二进制，命令部分如下。本轮只修改 markdup，
直接复用这些保留的阶段输出回归，没有重新执行前三步：

```bash

  -o ../performance_test/workflow_smoke_20260927.collate.bam --compress-level 1 -m 8G -n 66
fixmate -i ../performance_test/workflow_smoke_20260927.collate.bam \
  -o ../performance_test/workflow_smoke_20260927.fixmate.bam --compress-level 1 -m

  -o ../performance_test/workflow_smoke_20260927.sort.bam --compress-level 1 -m 8G
```
