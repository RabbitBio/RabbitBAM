## 修改范围

生产代码只有两处局部调整：

1. [分区建表](../../swbam-app/algorithms/markdup/swbam_markdup_mpi.cpp)：`MdBuildFirstCoordBoundaries` 只使用有效参考编号和位置建立 owner 范围。非空但只有未定位 unmapped 记录的尾部 rank 不再被误认为坐标倒退；记录仍进入输出，必要时沿用已有保守窗口。真实非空状态、记录数和输入次序不变。
2. [窗口释放](../../swbam-app/algorithms/markdup/swbam_markdup_stream_mpi.cpp)：普通窗口由 `key.this_coord + L <= progress_pos + 1` 改为严格 `<`。当某批结束于 `key+L`，后续批仍可能含同 POS 的候选，因此等号处保留状态。single、pair 及 paired-presence marker 复用同一个判断；只增加一个坐标位置的保留余量。

没有修改去重键、质量得分、QNAME tie-break、owner 映射规则、32+32 block 探测、MPI 消息格式、CPE kernel、双缓冲或压缩调度。没有将 paired-key 的释放锚点改为 SAMtools 队列使用的 single-key，也没有扩大为 `2L` 普通窗口。

`-l` 的输入位移约束和 block-aligned record 假设不变；本轮不声称解决任意超长 D/N/H CIGAR 下与 SAMtools 的完全等价问题。

## 主机回归

- [窗口测试](../../tools/markdup_window_test.cpp)：原有多批次、边界增量状态、marker 合并、QNAME、同分和远端决策回归全部通过。新增 single/pair 各方向及左右角色在 `K+L-1`、`K+L`、`K+L+1` 的释放检查，并确认后续更高分候选可替换旧 winner；另验收等号处保留 paired-presence marker、压制后续 singleton。
- [Halo 测试](../../tools/markdup_halo_plan_test.cpp)：POS 选择、partial 预处理不提前 KEEP、marker 保留及后续 winner 替换通过。
- [MPI 建表测试](../../tools/markdup_routing_test.cpp)：本机六 rank 检查 mapped+unplaced 尾部、空 rank、全 unplaced、重复坐标 cut，确认相同 key 从所有 source rank 得到相同 owner；下降的 mapped 起始坐标仍被拒绝。

修改前，新增的窗口等号断言和 mapped+unplaced 尾部建表断言均失败；修改后通过。因此不是只编译了未触及缺陷的旧测试。

这些是实际生产 MPE 函数的主机逻辑回归，不是模拟 CPE 性能。

## Sunway MPI/CPE 小样

构建 `RabbitBAM-MPI` 和 `swbam-markdup-halo-regression` 通过。有效作业 **9413906**，`q_share`、一节点六 MPI rank，每 rank 64 CPE，交互启动器退出状态为 0。

| case | 样例 | 验收 |
| --- | --- | --- |
| 0 | 完整首尾探测 | 预处理启用，通过 |
| 1 | 最后 rank 的 mapped/unmapped 混合尾部 | 预处理与输入处理通过 |
| 2 | 头部 32 block 覆盖不足 | partial 模式，不提前 KEEP |
| 3 | 尾部 32 block 覆盖不足 | partial 与关闭预处理的输出记录字节及次序一致 |
| 4 | halo 边缘、key 支撑范围未闭合 | winner 仍留给主扫描 |
| 5 | 部分覆盖下的 paired 候选与 marker | partial 与关闭预处理的输出记录字节及次序一致 |
| 6 | 最后非空 rank 全部为 unplaced unmapped | 不再报错；每 rank 64 条记录全部保留，DUP=0 |
| 7 | 六 rank 全部为 unplaced unmapped | 每 rank 64 条记录全部保留，DUP=0 |
| 8 | 普通窗口在 `key+L` 处跨 batch 出现更高分记录 | 每 rank 128 条记录中仅第 2 条被标 DUP，第 65 条保留 |

case 8 的关键输入：低分记录 `POS=5000,1M`；第一批在 `POS=5300` 结束；下一批的高分记录 `POS=5300,300H1M`，两者 key 都为 5000。各 rank 加独立坐标偏移。中间填充记录为 secondary，只推进扫描位置，不参与判重。这是专门探测等号条件的合成样例，不是普通短读数据的代表性能输入。

测试通过实际 CPE 解压、解析、候选提取及生产单遍处理函数，输出 BGZF 再独立 inflate 并检查 CRC、记录长度与精确 DUP 成员。不是单独伪造候选后就宣称 CPE 通过。case 0/1/2/4 主要检查 probe/plan；case 3/5/6/7/8 包含完整 rank-local 单遍输出。

本轮没有新增 SAMtools 全量对照，也没有重复 D1–D3 验收；窗口测试包含现有全量 hash 参考比较，case 8 使用明确的预期成员。历史 D1–D3 验收和本轮小样属于不同层次的证据。
