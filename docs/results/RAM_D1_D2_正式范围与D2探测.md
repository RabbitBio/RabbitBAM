如 D2 sort 工作预算为 61.34375 GiB，允许的算法预算约 53.676 GiB，
本轮显式使用 48G。SDK 单 rank D2 BAM 回环采用池 76G，自动工作预算仅
1.34375 GiB，因此列为独立容量关卡，不能按六 rank 的余量推断它一定成功。

边界/延后缓存取 `min(256 MiB, max(8 MiB, work / 16))`；
本轮六 rank 配置均得到 256 MiB。fixmate 为每个保留组/交换缓存分配
其中的 1/8（32 MiB），markdup 解码暂存约 64 MiB 一个临时文件轮换。
最终输出循环的搬运缓冲最多 8 MiB。完整 rank body 和最终文件仍占用 RAM 池，
自动小缓存不是完整输出容量上限；RAM 池耗尽明确失败，不自动落物理盘。

容量核对需要保留 RAM 页使用峰值、算法现有工作集统计及预算。
这些不足以宣称已经得到每个功能完整、严格的堆/RSS 峰值。
论文方法至少报告 RAM 池、`-m` 和自动预算规则；
内存峰值可作补充结果，除非主张空间优势，否则不必另做完整峰值扩展性矩阵。
RAM 模拟文件占用应与算法工作内存分列，不能作为真实 SSD 环境的算法内存使用。
