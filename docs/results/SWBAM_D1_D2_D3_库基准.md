## 2. 时间与正确性边界

主指标为 SDK 打印的 `core`，取各 rank 流水线墙钟时间的最大值：

- 不计入磁盘 load、全局 block scan/plan、最初的 body reserve 和最终 MPI 统计归约。
- 只读包括 batch 内存读取、CPE 解压/解析/count 和 MPE 批后归并。
- 读写包括 batch 内存读取、解析、pack、CPE 序列化/压缩及内存 body 写入。
- 读写不计完整 BAM header/EOF、输出汇集；不是 app 的 4.1~4.6，也不是磁盘 wall。

每次检查进程成功退出、实际 ranks、records、blocks、input_bytes、core>0；读写
还需 body_bytes>0，且示例内部要求 kept=total。沿用小数据回归已通过的实现，
本轮为避免 dump 成本不做 D1 全字段对照，不能表述为“已证明 D1 每个输出字节正确”。

`submit_wall_s` 另记整个提交等待时间，包含传输、排队、load、核心与 MPI 生命周期，
只用于估计何时跑完，不用于计算库吞吐量。

## 10. D3 SDK 分块模式准备与探测

D3 输入为 `D3-WGS-85G.coordinate.bam`，实际 **89,994,058,306 bytes**、
**1,210,633,370 records**。整文件 memory backend 无法同时容纳 D3 输入和单 rank
读写输出，因此两个 SDK 示例增加 `--chunked-memory`：按 BGZF block 分段，每 rank
每次最多预读 2 GiB 压缩数据；读写使用 256 MiB 循环内存 sink，实际执行每次
`Append()`，但不保留整份输出，也不 dump。仅修改 `examples/` 和基准脚本，
没有修改库的 BAM 算子和 CPE kernel。`--chunked-memory=64` 可用于小样本跨段回归。

`core` 为每 rank 各段的流水线时间之和再取 MPI 最大值，包含分段间重复的流水线
初始化/flush；`simulated_total` 额外计入 header open、缓存索引的内存分区/广播、
输出缓冲准备和结果归约。物理索引准备 `index_prepare`、段预读 `stage_read` 和为
预读分配/初始化缓冲的 `stage_prepare` 单独报告，不计入这两个指标。索引缓存根据
输入大小、mtime 和 body offset 校验，首次建立，后续重复使用。此时间边界不含
MPI_Init/Finalize、完整 BAM header/EOF 组装和最终文件输出，不能当成进程 wall。

0.25G 小样本的 1 核组回归：完整模式与 64 MiB 分块模式均为 **2,668,351 records**、
**275,206,630 body bytes**；在计时结束后计算的完整压缩 body FNV-1a 指纹均为
`f371847dfc1e8eac`。6 核组分块模式的记录数和 body 大小也一致。该回归验证了
多段输入不漏记录、读写 flush 不漏数据；它不能代替 D3 每条记录的独立语义比对。
