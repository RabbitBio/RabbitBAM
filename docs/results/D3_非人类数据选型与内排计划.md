## 准备与验收步骤

1. 只下载首选两个 FASTQ，校验完整 MD5、gzip 完整性、read 数及 mates 的 QNAME 一致性。若不通过，停止准备，不静默换数据。
2. 按用户要求沿用 fat 处理，固定 Ensembl release 115 的 GRCm39 primary assembly、BWA 0.7.18、samtools/HTSlib 1.20 及参考摘要，一次性生成保留所有记录的 BAM。不要先删重或仅保留唯一比对；比对与数据准备不计入 SWBAM/samtools 操作性能。
3. 按现有 SDK 的“记录不跨 BGZF block”约束准备统一 BAM，确认 header、EOF、CRC 及完整记录流摘要。当前 HTSlib 1.20 写入使用 `bgzf_flush_try`；先审计输出是否已经符合约束，若通过则不额外重打包。如果未通过，停止而不是分发不兼容输入；后续重打包必须验证前后完整记录流一致。`io-check` 负责检查，不自动重分块。
4. 记录实际 BAM/SAM 大小、记录数、读长、配对/比对/secondary/supplementary 比例、重复标记状态和长记录上限。数据准备结束前不宣称规模、内排或容量已验收。
5. a4 与 swls 使用相同准备后 BAM 及摘要，先做小数据正确性与一次全量容量探测。RAM 池覆盖输入、暂存、最终输出；算法工作区另计。
6. sort/collate 的 `-m` 选择能够容纳该数据的已验证值，并检查日志确实走内排、没有 spill。若容量不够，先定位容量组成，不将外排样本混入内排成绩。
7. 正式范围为两个 SDK、八项 app 和普通四步串联，沿用现有资源点、三轮重复、统一输出路径及 processing/MPI 区间口径。a4 单独筛选线程数，collate 均固定 `-n 66`，其余语义参数与 D1/D2 对齐。
8. 不新增 D3 外排矩阵，也不重跑 D1 消融。等待时间在完整下载、比对和首次全量探测后按实测估算。
