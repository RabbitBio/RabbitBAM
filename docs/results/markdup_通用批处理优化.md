## 目标与实现

D1、D2、D3 使用相同的单遍处理实现，不识别数据集名称、不增加数据集专用参数。保留现有 key、score、QNAME/global-order tie-break、过期条件、边界覆盖检查、候选路由及有界暂存。

1. **批内间接哈希表**：存储 hash、代表候选索引和赢家索引，不再把完整 key 复制到表中。候选及 carry 在本批结束前有效；hash 命中后仍比较完整 key，不以指纹代替相等性判断。single winner 被 paired-marker 淘汰后，代表索引仍有效。
2. **代际标记复用**：独立的一字节 generation tag 标记本批有效槽位。每批递增 generation，分配或 255 代回绕时清空 tag，避免每批清零整个 24-byte 槽位数组。过期索引不再访问，不改变窗口有效期。
3. **paired-marker 合并统一化**：所有 optimistic 单遍窗口都只保留每个完整 single key 的一个存在标记，不再仅在保守边界模式启用。只合并 metadata，不合并 BAM 记录或真正的赢家。
4. **Pending 只通知一次**：carry 中的赢家第一次保留时已设置 Pending；后续批次不重复回调。新赢家仍 Pending，败者仍 DUP，窗口闭合仍最终 KEEP。
5. **减少候选整理**：按 CPE block 批量追加连续候选，再修正 pair QNAME offset；每次 exchange 预先确定后继非空 rank，避免每条候选重复搜索。无闭合 key 时跳过空的安全检查循环；有闭合 key 时保留原检查。
6. **持久表插入复用**：负载未达扩容阈值时，一次 probe 完成查找/插入；仅在阈值处先确认 key 是否已存在，避免不必要扩容。不改变持久边界的释放条件。
7. **普通窗口 QNAME 字节区复用**：跨批次存活的赢家继续使用原 offset，只为新赢家追加名字；所有本批查找结束后，若死字节超过活字节且总量超过 1 MiB，则按下一批赢家批量压紧、更新 offset。没有活名字时清空。字节区使用量受当前活名字和小窗口余量约束，不随文件长度一直增长；容器 capacity 仍可能保留历史峰值。

最终收尾版另对空 QNAME 的 carry offset 归零，避免在清空名字区后留下旧 offset；新增非空名字过期、空名字跨批保留的回归。此后冻结最终程序，正常数据集性能单独记录，不混合不同程序指纹计算正式中位数。

64-bit 构建中，批内表理论存储从旧版约 49 B/slot 降到 25 B/slot（24-byte 索引槽位 + 1-byte tag）。这是这一张表的大小，不是总 RSS、RAM storage 峰值或整个算法内存的降幅。跨 rank 保守边界的持久表保持原实现。

## 实验设置

- 六节点，每节点一个 MPI rank / 活跃核组，每 rank 64 CPE；其他核组提供大共享内存。
- `-N 6 -np 1 -mpecg 6 -cgsp 64 -share_size 100 -cross_size 88000 -cache_size 32 -xmalloc`。
- 同一预处理输入：D1/D2 为原 fixmate.sorted BAM；D3 为小鼠 SRR7768905 的 fixmate + sort 输出，不是旧的人类 85 GB 数据。
- `markdup --stream -l 300 -m 8G --compress-level 1 --storage ram --ram-ranks 6 --no-dump`。
- RAM 容量 D1 为 8G/rank，D2/D3 为 24G/rank。完整输出仍写入 RAM；不计物理 preload / dump。
- 主指标为 `[swbam-processing]` 的六 rank 最大值，同时保存 4.3、分阶段时间、候选通信、输出大小、RAM 暂存及内存跟踪。
- 各版本独立冻结，不覆盖旧二进制；首轮为单次诊断，不替代正式三次中位数。不同作业使用不同节点，可同时预加载，不能据此评价物理磁盘性能。

compact 的 D3 探测时间下降，但 `flat_init` 最大值从约 0.154 s 升到 3.501 s，抵消了收益。D2 更明显：`flat_probe` 从约 37.827 s 降到 28.608 s，清表却从约 0.851 s 升到 20.412 s。大表保留历史容量后，每批清零的成本较高；generation 的 D2 `flat_init` 降到约 0.047 s。没有只保留最快样本或把失败的尝试删去。

generation 单次相对同轮 baseline 的 processing 缩短：D1 8.90%、D2 21.97%、D3 4.84%。本阶段未宣称三次中位数，也未将阶段最大值简单相加作为关键路径。

reuse 的 D3 单次未显示单独收益（100.142459 s 对 generation 的 99.686334 s），不把单次约 0.46% 的差异直接认定为噪声或确定回归。arena 在此基础上进一步缩短 D3 的 `group_scan`，首轮约 92.49 s；另以相同冻结指纹进行三个数据集的第二次确认。

## 验证与复现

- 主机窗口回归：强制全 hash 碰撞、已淘汰 single 的查找、连续 600 批 generation 回绕、多批赢家替换、QNAME、marker 先后顺序及远程判定。
- 完整覆盖和保守窗口均检查 Pending 只通知一次、同 key marker 合并；与原 full-hash 参考逐记录决策比较。
- 缓存的 owner 上界与原搜索结果对比，覆盖空 rank、重复分界坐标及跨参考序列。
- QNAME 字节区回归：100 批不断过期的 pair key 与一个长驻 key 共存，强制多次压紧；最后由同分、字典序更小的 QNAME 替换长驻赢家，与完整 hash 参考一致。覆盖普通/保守窗口的随机混合判重，ASan/UBSan 与泄漏检查通过。
- final 额外覆盖旧非空名字过期、空名字跨批保留时 offset 归零；两 rank 回归 `9080276` 六项通过，小样本 `9080281` 的 200,000 records / 22,259 DUP 及全部记录字节、顺序、CRC 与已验证参考一致。
- compact / unified 的两 rank CPE/MPI 六项回归通过；20 万条输出与已验证参考的全部记录字节、顺序、CRC 一致（200,000 records，22,259 DUP）。
- 全量实验另核对六 rank 成功、记录数、DUP、完整输出大小和通信。生成阶段计数一致不能等同于全量逐记录比较。

generation 的 D1/D2/D3 六 rank 均成功，完整输出依次为 12,192,952,100 / 40,718,592,510 / 16,614,394,500 B，与同轮 baseline 完全一致。RAM 池最大峰值依次为 4,102,029,312 / 14,168,358,912 / 6,211,764,224 B，临时数据累计读、写各为 847,602 / 13,766,224,386 / 16,457,456,316 B，均未减少。
