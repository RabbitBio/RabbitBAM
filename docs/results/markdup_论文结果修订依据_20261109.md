# 新版 Markdup 与完整去重流程：论文修订依据

更新日期：2026-11-09。对应论文 Results 中的 `Distributed BAM processing` 和 `Deduplication Workflow Performance`，以及摘要、结论中的汇总加速区间。

本轮只修订论文、对应中文直译和本文档，不修改算法、不提交新作业，也不覆盖原始实验记录。所有时间单位均为秒，MB/GB 为十进制；MiB/GiB 为二进制。

## 1. 正式结果及统计口径

使用 2026-11-09 定向正式重测的三次样本，不将 11 月 8 日的单次优化诊断或大缓存实验混入正式中位数。

配置为六节点、每节点一个 MPI rank 和一个活跃核组、每 rank 64 CPE。Markdup 参数统一为 `--stream -l 300 -m 8G --compress-level 1`；D1/D2/D3 使用同一路径，没有数据集专用算法分支。

SWBAM 取六 rank 最大 processing 时间，排除物理 preload/dump 和 MPI 初始化、结束；完整 RAM 输入、压缩、暂存和输出组装仍计入。SAMtools 沿用 A4 NVMe 文件的进程 wall time。因此加速比是既定跨平台、跨存储计时条件下的比值，不是同硬件同存储的纯软件比较。

## 2. 数据集差异的直接证据

下表取正式第 1 次独立 Markdup 日志。三轮计数和字节量一致，阶段时间相近，但下列阶段值不是三次中位数。

| 指标 | D1 | D2 | D3 |
| --- | ---: | ---: | ---: |
| 输入记录数 | 177,798,571 | 365,079,492 | 165,373,770 |
| processing 微秒/记录，由正式中位数计算 | 0.261 | 0.359 | 0.559 |
| 边界预处理 | 完整覆盖 | 完整覆盖 | 部分覆盖、保守维护 |
| 主循环远程记录候选 | 0 | 0 | 541,474 |
| 主循环远程配对存在标记 | 0 | 0 | 547,945 |
| 主循环候选载荷，含标记及 QNAME / MB | 0 | 0 | 88.650061 |
| 主循环判定载荷 / MB | 0 | 0 | 8.663584 |
| 各 rank 累计候选处理 `group` 时间范围 | 14.394960–14.765912 | 25.188057–42.744847 | 15.055702–40.667581 |
| `group` 最大值/最小值 | 1.03 | 1.70 | 2.70 |
| 跟踪 pending-buffer 峰值 / MB | 16.846583 | 269.418086 | 282.562612 |
| 原始解码载荷暂存 / GB，每方向 | 0 | 0.127409080 | 2.389566787 |
| 压缩片段重排暂存 / GB，每方向 | 0.000847602 | 13.638815306 | 14.067889529 |

可据此撰写的结论：

- **D2 不是主扫描候选传输受限。** 主循环候选、标记和判定载荷均为零，但状态检查等集合通信仍存在。块数均衡不等于键查找、候选存活时间和窗口维护工作均衡，慢 rank 可能限制同步轮次的推进。
- **D3 不是完全关闭边界预处理。** 日志是 `enabled=1 partial=1 conservative=1`，预处理先确认 13,267 个 DUP，最终 KEEP 为零，剩余候选继续由主扫描维护。应删除旧文将其概括为全有或全无 fallback 的说法。
- **D3 的候选传输量不能直接解释全部时间差。** 88.65 MB 包含候选结构、配对存在标记及 QNAME，不包含 MPI 计数/状态消息；541,474 只统计真正的记录候选，不能误写成包括标记的总量。
- **记录数不能单独代表状态算法的工作量。** D3 的记录数少于 D1，但每条记录处理时间更长；窗口状态、rank 间不均衡及输出工作量都需要考虑。
- **阶段计时不是可直接相加的关键路径。** `group_scan` 是 `group` 的组成部分，其他时间也存在嵌套或重叠；`candidate_mpi` 只覆盖指定交换区段，不能代替全部通信和等待时间。
- **pending 峰值不是进程 RSS。** 表中是算法跟踪的最大 rank 值，不是六 rank 之和，也不包括整个 RAM 存储池。

新版实现用间接索引哈希表、generation 标记、QNAME 字节区复用、配对存在标记合并及一次性 Pending 通知减少 MPE 维护工作，但没有改变去重键、比较规则、过期条件和有界输出策略。论文不再用“只有 SAMtools 使用持久哈希表”来解释差异，因为 SWBAM 的边界状态也使用持久表。

## 3. 两种暂存与诊断实验的限制

原始解码块暂存用于释放仍有 pending 记录的载荷；压缩片段暂存用于在后续块先压缩后恢复输入顺序。二者在本实验中均走 RAM backend，不是临时数据真实落物理磁盘。

大缓存诊断只修改私有构建的缓存上限，并保留内存预算规则；不是去掉全部暂存机制。每种设置每个数据集只跑一次，节点和诊断开关等条件与正式矩阵不同，不能作为新的正式成绩或严格重复消融。

| 数据 | 默认缓存 processing | 大缓存 processing | 本对照时间缩短 | raw spill 批数 | 不变的压缩暂存 / GB，每方向 |
| --- | ---: | ---: | ---: | --- | ---: |
| D2 | 138.149338 | 137.687259 | 0.33% | 33 → 0 | 13.638815306 |
| D3 | 92.506219 | 90.907103 | 1.73% | 594 → 0 | 14.067889529 |

因此，正文使用受限表述：**没有观察到消除 raw spill 带来大幅提速；这一对照尚未隔离压缩片段暂存及全部缓冲调度成本。** 不能写成“所有暂存开销均可忽略”，也不能用累计暂存 GB 数替代耗时。

## 4. 流程阶段占比如何计算

选取每组总时间恰为中位数的实际轮次，而非将阶段中位数拼接：

| 配置、轮次 | Collate | Fixmate | Sort | Markdup | 本轮总和 | Markdup 占比 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| D1，第 1 轮 | 59.444080 | 36.178275 | 50.942056 | 46.422784 | 192.987195 | 24.1% |
| D2 外排，第 2 轮 | 157.352926 | 84.704161 | 149.740904 | 131.458777 | 523.256768 | 25.1% |
| D3，第 2 轮 | 56.778295 | 33.410488 | 46.483473 | 92.455792 | 229.128048 | 40.4% |

D2 外排的 `(collate + sort) / total = 58.7%`，包含提取、排序、重分布、run 生成、归并和压缩等阶段工作，不能称为“外排 I/O 占 58.7%”。

新版 D2 独立 Markdup 的 2.30 倍已高于 Fixmate 的约 2.09 倍，所以旧文“Markdup 是 D2、D3 上加速最少的阶段”必须删除。D3 中 Markdup 仍占约四成流程时间；D2 外排则需要同时解释 collation/sort 的成本。

## 5. 正确性证据与未覆盖范围

- 正式独立 Markdup 首轮保存完整输出并复读；后两轮仍生成完整 RAM 输出，但不保存物理文件。
- 全部四组、12 轮流程的 sort 与最终 Markdup 输出均完成完整复读，记录数、坐标顺序和最终 DUP 总数符合预期。论文表中使用其中三组、九轮。
- D2 外排通过实际 external 模式、非零临时读写、run 数及 8 GiB 跟踪工作集验收。
- 本次正式重测不等于新 Markdup 已完成全量跨工具逐字段或 DUP 成员集合比较；这些工作另由[同输入正确性验证](同输入正确性验证_20261109.md)跟踪，不将未完成结果写为已通过。
- D3 SAM-to-BAM 的旧错误成绩及其独立修复版不是本次 Markdup 修订范围，没有据此修改流式应用表。
