# D1/D2/D3 库基准汇总

## 1. 测试目的与口径

本文合并 D1、D2、D3 的 BAM 库基准，包含两类测试：

1. **Samtools 基线**：在 A4 x86 服务器上从 bigssd 读取 BAM，测试只读扫描和
   BAM read-write 回环的端到端 wall time。
2. **SWBAM 基线**：在神威集群上使用 memory backend，测试 Optimized read 和
   read-write 的内存驻留核心时间，排除输入 load 和最终 dump。

两类时间可用于观察各自平台的扩展性和性能上界，但不是严格统一 I/O
介质和计时边界的跨平台端到端比较。

## 7. SWBAM D1 扩展性

### 7.1 环境与口径

| 项目 | 配置 |
|---|---|
| 平台 | `swls` 神威集群，`q_share` 队列 |
| 程序 | `RabbitBAM-MPI`，Optimized path |
| 节点/rank | `1/2/4/6/8/16/24/32/48`，每节点 1 rank |
| 计算资源 | 每 rank 使用 1 MPE + 64 CPE |
| 大共享 | `-mpecg 6 -share_size 100 -cross_size 88000 -xmalloc` |
| 输入 backend | `memory`，每 rank 加载完整 D1 |
| 重复 | 每点 3 次，报告中位数 |

`-mpecg 6` 为每个 rank 提供约 85 GiB 可用 cross heap，但算法仍只启动
64 个 CPE。其余 5 个核组主要提供内存容量，不参与核心计算。

- 只读主指标：`444Complete the total body cost`。
- Read-write 主指标：`Complete the total (4.1~4.6) cost`。
- 两者都排除输入文件加载和最终验证输出 dump。

## 8. 6 核组与 A4 整机结果对照

6 核组配置为 `-N 6 -np 1`：6 个 MPI rank 分布在 6 个节点，每个 rank 使用
1 MPE + 64 CPE 计算。它使用了 6 个节点的内存容量和带宽，不是“单神威节点”。

| 测试 | SWBAM 6 核组核心时间/s | A4 Samtools 最佳 wall/s | 时间比 `Samtools/SWBAM` |
|---|---:|---:|---:|
| 只读 | 2.794902 | 11.36 (`-@8`) | **4.06x** |
| Read-write level 1 | 9.263192 | 31.29 (`-@48`) | **3.38x** |

按当前核心时间口径，6 个神威计算核组已超过 A4 整机的 Samtools 最佳
实测时间。但 SWBAM 排除 load/dump，Samtools 包含 bigssd I/O，因此正式论文中
必须将其表述为“当前计时边界下的性能对照”，不应包装为统一 I/O 的端到端加速比。

## 9. Composable SDK 初步探测

D1 上使用 1 rank/64 CPE 的单次核心时间：

| SDK 路径 | 核心时间/s | Records/s | 输入 GB/s | 输入+输出 GB/s |
|---|---:|---:|---:|---:|
| Raw read | 62.831 | 2.830 M | 0.157 | - |
| Raw read-write | 134.336 | 1.324 M | 0.074 | 0.159 |
| `bam1_t` read | 158.383 | 1.123 M | 0.062 | - |
| `bam1_t` read-write | 445.479 | 0.399 M | 0.022 | 0.048 |

Composable 路径的主要瓶颈不是 CPE BGZF 解压，而是 MPE 侧 Raw record-view 构造/
遍历、`bam1_t` payload 物化和反向编码。该结果是优化动机，不是与 A4 Samtools
的正式跨平台加速比：前者只使用 1 rank/64 CPE，并且两者 I/O 口径不同。

## 11. 正确性与局限

- Samtools 只读的所有轮次都得到预期记录数，read-write 输出均通过
  `samtools quickcheck`。
- SWBAM D1 的 27 次只读均处理 `177,798,571` 条记录，27 次 read-write
  均报告 `total_records=kept_records=177798571`、`dropped_records=0`。
- SWBAM 保留的 1 rank、6 rank 和 48 rank 输出大小均为 `11,467,682,880 bytes`；
  1 rank 和 48 rank 输出的 `stats --basic` 结果一致。
- SWBAM 当前 memory backend 会让每个 rank 复制加载完整输入，大规模启动
  会对共享文件系统造成压力。
- A4 Samtools 时间包含真实 I/O，SWBAM 核心时间不包含 load/dump；图表和论文
  必须始终标明这一区别。
