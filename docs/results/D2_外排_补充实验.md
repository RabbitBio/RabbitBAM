# D2 外排补充实验：A4 与 SWLS

## 范围与计时

2026-10-14 启动独立补测：D2 的 collate、coordinate sort 各三次，以及普通
`collate -> fixmate -> sort -> markdup` 四步串联三轮。保留已完成的 D1/D2
内排成绩，不覆盖历史结果。没有修改 SDK、app 算法或从核 kernel。

- SWLS：六节点，每节点一个活跃核组、64 CPE，继续用 RAM 存储模拟 SSD。
  collate/sort 每 rank `-m 8G`，算法预算合计 48 GiB；先以每 rank 64 GiB
  RAM 池探测完整输入、runs、接收段和输出容量。算法工作区另计。
- A4：samtools 1.20，sort 合计近似 arena 预算 48 GiB，实际 RSS 另记。
  对 `-@ 24/48/96/127` 各粗筛一次，最好两项及旧配置 24 各确认三次，
  以确认中位数选择本轮外排配置，随后用于三轮串联。
- 两边 collate 均为 `-n 66`。A4 使用普通临时文件 collate、`-@ 127`；
  samtools collate 没有 `-m`，因此不宣称其工作内存与 SWBAM 对齐。
- A4 fixmate `-@ 127 -m`，markdup `-@ 24 -l 300`，保持此前 D2 选参。
  SWLS fixmate 添加 mate-score，markdup `--stream -l 300 -m 8G`。
- BAM 压缩级别均为 1；A4 临时数据和最终输出写实际 NVMe。

SWLS processing 从 `MPI_Init` 返回后至 `MPI_Finalize` 调用前，MPI 区间
从 Init 调用前至 Finalize 返回后；两者各自取 rank 最大值。实际 RAM 临时读写、
最终文件完整组装均计入，准备和 Finalize 后保存不计入。
`--no-dump` 仅用于独立性能项第二、三次，完整 RAM 输出仍然生成；普通串联
每一步均保存，下一命令重新预加载。四步成绩为逐轮四次实测合计，再取中位数。

A4 计时使用 GNU time wall，包含真实输入、临时文件、最终输出 I/O；四步也采用
四条命令 wall 逐轮合计。quickcheck、全量计数、flagstat/排序正确性复读在计时外。
不清除系统缓存；有输入准备与粗筛，记录轮次、RSS、实际文件系统 I/O 计数。

## 关卡与验证

SWLS 独立驱动先执行一轮探测流程和 sort/markdup 全量复读，共六条命令。
要求各 rank 的 processing/MPI 区间总结齐全且 `status=0`，总记录数
365,079,492；collate/sort 必须走 external 路径，实际产生多 runs 和非零
RAM 临时读写，不能只凭 `mode=external` 接受成绩。最终坐标有序，duplicate
bit 为 8,894,488。全部通过后自动启动正式矩阵，容量失败或异常则停止。

SWLS 共 32 条命令：探测/复读 6、独立性能 6、独立输出复读 2、普通流程
12、流程排序与重复标记复读 6。探测不导入正式中位数。

A4 监测独立临时目录中的文件数量和大小，确认 collate 真正写临时文件；
sort 必须有 `merging from N files` 且 N > 0。首次确认样本做完整计数，
每轮最终输出全量检查记录数、重复数与排序。临时文件元数据采样间隔 1 秒，
其峰值是采样观察值，不是准确的瞬时磁盘空间峰值。

本轮预算约束算法工作区；RAM 池作为存储另计。sort/collate 目前会在执行结束
时释放 runs 和接收段，不能用内排 RAM 池容量推断外排一定可运行。
RAM-backed external-memory 不等同于真实 SSD 的外排性能。
