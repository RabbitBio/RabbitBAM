app 池和 `-m` 与通过的容量配置一致。collate 固定 `-n 66 -m 48G`，池 16G；
sort `-m 48G`，池 16G；fixmate 池 24G、`-m` 添加 ms；markdup 池 24G、
`--stream -l 300 -m 8G`；过滤池 16G；转换池 40G；flagstat 池 8G。
正式 sort 不启用分配诊断。SDK 扩展性中的其他资源点首次运行也受同样的失败检查。

独立 app 可使用 `--no-dump`，仍构建完整输出。SDK 回环和 SAM->BAM 首轮
默认保存并复读。每轮工作流从初始 BAM 重新生成自己的全部中间文件，
四个命令都在 Finalize 后保存，后继重新预加载，不复用旧实验的阶段成绩。

每个正式点取三次 MPI 区间 max 的中位数。工作流逐轮将四个 MPI 区间 max
合计，三轮合计再取中位数，不用四个独立阶段中位数之和代替。
`results.tsv` 留存准备耗时、4.3/core、RAM 页使用峰值和完整输出大小；
`workflows.tsv` / `workflow_summary.txt` 分别登记逐轮合计和流程中位数。
准备/保存不计入 MPI 区间，实际等待时间仍包括它们；不作时间扣减。

## 启动与冻结

源码入口 `tools/ram_d2_matrix.sh` 使用共享 `tools/ram_matrix.sh` 和
`tools/ram_metrics.awk`。D1 本地入口也复用共享驱动，但远端正在运行的 D1
仍使用自己的旧冻结脚本，没有原地替换。
独立根目录保存完整 `launch.sh`、`commands.sh`、输入大小与版本指纹。

```bash
export BENCH_D2_BASELINE_ROOT="$PREVIOUS_D2_PROBE"
export BENCH_WAIT_FOR="$RUNNING_D1_MATRIX"
nohup bash "$ROOT/bin/ram_d2_matrix.sh" "$ROOT" \
  "$D2_BAM" "$D2_SAM" "$D2_COLLATED" "$D2_FIXMATE" "$D2_SORTED" \
  > "$ROOT/driver.log" 2>&1 < /dev/null &
```

`BENCH_STAGE=capacity` 可只完成关卡；实际后台本轮为默认 `all`。
`BENCH_RESUME=1` 可复核成功日志并续接已有作业，不重复提交已成功样本。
失败作业不能靠 resume 冒充成功；本轮首个启动失败采用新目录保留原记录后重提。
D1 失败则不启动 D2 正式矩阵，等待 D1 的上限为 24 小时。

调度配置仍为 `-N ranks -np 1 -health 1 -mpecg 6 -cgsp 64`，
大共享 `-share_size 100 -cross_size 88000 -cache_size 32 -xmalloc`，
`-a mpi -b -K -q q_share -timelimit 03:00:00`。
每命令提供对应 `--ram-ranks`、唯一会话、显式容量和 5400 秒准备超时。
`-K` 不是阻塞等待完成，驱动通过 `bjobs` 轮询并核对日志。
