# Samtools D1/D2/D3 应用基准结果

## 1. 测试目的

本轮测试用于建立 SWBAM 各应用的 Samtools 对照基线。库微基准中已经测试过
只读扫描和 BAM read-write 回环，因此本文重点记录统计、格式转换、过滤、
collate、fixmate、sort、markdup 和完整去重流程。

所有时间均为 A4 服务器直接读写 `/home/bigssd` 的端到端 wall time，
包含真实文件 I/O。

## 5. 完整去重流程

流程为：

```text
collate -n 64 -l 1
  -> fixmate -m, BAM level 1
  -> coordinate sort, BAM level 1
  -> markdup, BAM level 1
```

| 数据集 | 阶段线程 `collate/fixmate/sort/markdup` | 三次 Wall/s | 中位数/s | 约合计时间 |
|---|---|---|---:|---:|
| D1 | 96 / 96 / 24 / 127 | 575.412 / 554.475 / 641.709 | **575.412** | 9.59 min |
| D2 | 96 / 96 / 24 / 127 | 1430.051 / 1458.559 / 1383.183 | **1430.051** | 23.83 min |
| D3 | 96 / 96 / 96 / 127 | 5156.258 / 5268.722 / 4801.213 | **5156.258** | 85.94 min |

各数据集独立阶段中位数之和分别为 `551.95 s`、`1423.83 s` 和
`4973.91 s`。完整流程中位数分别高出约 4.25%、0.44% 和 3.67%，
主要反映不同轮次的系统波动、临时文件与 page cache 状态差异。

## 6. 代表性命令

```bash
S=/home/user_home/wzs/software/samtools-1.20/bin/samtools
IN=/home/bigssd/wzs_data/D1-WES-9G/initial/D1-WES-9G.coordinate.bam

# 统计
$S flagstat -@ 8 "$IN" > flagstat.txt
$S stats -@ 24 "$IN" > stats.txt

# 格式转换与过滤
$S view --no-PG -@ 96 -h -O SAM -o output.sam "$IN"
$S view --no-PG -@ 24 -O BAM,level=1 -o output.bam input.sam
$S view --no-PG -@ 96 -q 30 -O BAM,level=1 -o filtered.bam "$IN"

# 去重各阶段
$S collate --no-PG -@ 96 -n 64 -l 1 -T tmp/collate -o name.bam "$IN"
$S fixmate --no-PG -@ 96 -m --output-fmt BAM,level=1 name.bam fixmate.bam
$S sort --no-PG -@ 24 -m 7864M -l 1 -T tmp/sort \
  -o fixmate.sorted.bam fixmate.bam
$S markdup --no-PG -@ 127 -l 300 -T tmp/markdup \
  --output-fmt BAM,level=1 fixmate.sorted.bam markdup.bam
```

sort 的 `-m` 是每线程内存上限。D1/D2 在选定的 `-@24` 下使用
`7864M`，总预算约 192 GiB；D3 在 `-@96` 下使用 `506M`，总预算约
48 GiB，强制产生 external runs。

## 7. 正确性与局限

- 所有生成的 BAM 都通过 `samtools quickcheck -v`。
- 同一数据集、同一应用的三次输出大小一致。
- 完整流程输出大小分别为 D1 `11,857,809,071 bytes`、
  D2 `39,588,687,990 bytes`、D3 `103,289,606,678 bytes`。
- D3 BAM→SAM 文本输出达 `532,628,139,096 bytes`，说明该项会强烈受 NVMe
  顺序写带宽影响。
- `samtools stats` 计算的指标明显多于 SWBAM `stats --basic`，两者时间
  不能直接作为严格加速比。
- MAPQ≥30 输出已经 quickcheck，但本轮脚本没有额外保留 kept-record 数量；
  与 SWBAM 做正式正确性对比前需补一次记录数核对。
- 线程选择基于每个候选点单次试跑，可用于避免明显较慢的配置，
  但不能证明所选线程数是绝对最优。正式表使用的是选定配置下的三次中位数。
