# markdup 已决压缩与追赶验证

更新：2026-10-13。本次为独立功能/性能探测，不替换正在运行的 D2 正式矩阵。

## 实现

- `MdOnePassQueueReady` 在本批判重与远端决策交换完成后，将全部已决块加入有序压缩队列。
  未决块不再阻挡后续已决块的压缩。Waiting、Ready、Compressing、Stored 区分
  决策、从核借用和暂存生命周期，拒绝对已封闭块追加决策。
- `MdOnePassRelievePressure` 同时检查驻留原始缓冲区及已决块积压，超过自动缓存预算时
  额外压缩到低水位；没有已决块时继续输入，不等待未决窗口。原始数据转存只允许未决块。
- 保持正常批次 64 块分配/复用。内存紧张时，跳过已压缩块，只转存未决块并释放整批空间。
  转存后按需要读取单个块，压缩完成即释放，不再整体读回已完成或尚未需要的块。
- app 私有 `OrderedBody` 在没有越序时直接使用原 rank-body；第一次跳过未决块后，
  将剩余压缩数据写入带 key 的 64 MiB 临时段，最终排序索引、合并连续区段。
  一个输入块可对应多个输出 BGZF 块，key 同时编码输入块序号和输出子块顺序。
- 最终输出直接从逻辑有序的数据源读取并写到输出，不额外复制成另一份有序 rank-body。
  RAM/POSIX 共用相同片段逻辑，RAM 仍执行实际读写；只有一个物理段的全部逻辑片段
  消费完后才回收该段，防止乱序消费释放尚未读取的数据。
- 索引容量受预算限制，计算中也计入工作内存。当前 256 MiB 自动原始缓存对应
  64 MiB 索引预算上限；RAM 存储池容量仍单独约束输入、临时数据和最终输出。
- 四条流水线、从核 kernel、判重规则及 SDK 示例未修改。额外追赶不增加每批 MPI
  集体通信；局部暂存失败沿原有同步点传播，最终封闭输出后先同步成功状态再准备布局。
