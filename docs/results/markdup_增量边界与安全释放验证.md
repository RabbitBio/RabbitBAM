## 改动范围

仅优化 `halo=fallback` 的 one-pass 路径。正常 `halo=enabled` 仍调用原批内判重，不分配增量边界表、不增加通信；SDK、从核、codec、判重规则、批大小、压缩和完整 RAM 输出流程不变。

首、尾边界分别维护持久 flat hash 表。每个 pair key 只保存当前 winner 及其 QNAME，每个 single key 保存当前 winner 或 paired-marker 存在状态；新候选只查找、更新自己的 key。旧 winner 被替换时发出 duplicate 决策，新 winner 首次进入时标记 pending，不在后续批次重新遍历所有边界 winner。扩容采用几何增长，保留旧表内容，不按批清空。

存在边界候选的批次将非边界候选引用同一 QNAME 区域、按 metadata 收集后交给原普通窗口；没有边界更新的批次直接使用原候选数组。不复制完整 BAM 原始记录。两张边界表、winner/QNAME、metadata 容量及进度数组计入工作集跟踪，仍受原 `-m` 检查；不计成 RAM 存储池，也不隐藏输出或临时数据。

## 安全释放

回退时把已有 capture 状态 `Allreduce` 改为四个整数的 `Allgather`，不增加 collective 次数。内容是状态、是否仍有输入批次、扫描参考序号和坐标；正常路径保留原 collective。

以 cut 为中心、边界 key 范围为 `cut +/- L`，仅在可能继续贡献该边界的输入 rank 均已越过 `cut+2L` 或明确 EOF 后，释放对应首/尾表并发出最终 keep。使用与现有窗口一致的最长 read/clipping 参数契约，严格超过而非等于阈值。无坐标不冒充 EOF，空分片和异常状态不提供错误证明。较早 rank 即使其 aligned-start 分片末端较远，也必须推进或 EOF，不能忽略参考消耗很长的 CIGAR 产生的远端 end key。

证书在本批 capture 时收集，在本批候选全部交换、处理后才应用；随后经过原状态同步和决策回传。未获证明的边界保留到正常最终合并，不强行缩短依赖窗口。释放整个边界表，回收表、winner 和 QNAME 存储；历史峰值保留为保守工作集估计，不称为 RSS。
