## 关卡顺序

1. a4 用 samtools/HTSlib 1.20 从输入生成前 200,000 条完整记录的小数据及同一份 SAM，并生成 `collate -n 66 -> fixmate -m -> sort -> markdup -l 300` 对照。此前缀可能截断末端的配对组，两端工具使用完全相同的输入。
2. swls 用六节点、每节点一个活跃 64 CPE 核组跑两个 SDK、八项 app 和四步链路；SDK、sort、markdup、转换结果另做完整复读。所有正常输出实际保存，不用 `--no-dump` 跳过文件保存。
3. 将小数据结果送至 a4，检查 SDK/两种转换的有序字段与 AUX、过滤、collate 内容与 QNAME 连续性、fixmate 字段与 AUX 对照、sort 内容与顺序、markdup 记录数/顺序/重复总数。检查不要求 BAM 压缩字节或 PG 头相同；markdup 这里不声称已做全量逐记录跨工具对照。
4. 小数据通过后才进行同样的全量六核组容量关卡，保存普通四步中间文件，下一条命令重新预加载；末端不使用封装 workflow/pipeline 命令。
5. 额外探测两个 SDK 的单核组容量，为后续扩展性准备。至此停止，是否启动正式矩阵另行确定。

a4 同步做一次完整四步对照及全量过滤计数，使用 `-@ 24`，sort `-m 4096M`，压缩级别 1，collate 固定 `-n 66`。这只是可行性/正确性对照，不是线程调优或正式三次成绩。其资源门槛为可用内存至少 112 GiB、磁盘剩余至少 200 GiB，等待最多 10 分钟，避免无限等待。

## 容量配置

下表是本轮提交并通过全量关卡的容量配置，不是最小容量测定；markdup 仅通过容量/正确性关卡，性能关卡仍未通过。RAM 池是每 rank 的模拟存储总预算；算法工作区另计。

| 全量项目 | ranks | RAM 池/rank | 算法参数 |
| --- | ---: | ---: | --- |
| SDK count、flagstat、复读 | 6 | 8G | 流式 |
| SDK 读写、过滤 | 6 | 16G | MAPQ>=30；BAM level 1 |
| collate | 6 | 16G | `-n 66 -m 48G` |
| fixmate | 6 | 24G | `-m` 为生成 mate score 的布尔选项 |
| sort | 6 | 16G | `-m 48G` |
| markdup | 6 | 24G | `--stream -l 300 -m 8G`，使用独立新版程序 |
| BAM->SAM、SAM->BAM | 6 | 40G | 保存完整 SAM，再重新预加载转换 |
| SDK count | 1 | 16G | 覆盖完整输入 |
| SDK 读写 | 1 | 48G | 仅此项 `--no-dump`，完整 RAM 输出仍必须生成 |

统一申请 `-N 6 -np 1 -mpecg 6 -cgsp 64 -cross_size 88000 -xmalloc`，单核组两项改为 `-N 1`。`SWBAM_NODE_MEMORY=88000M`，就绪超时 5400 秒，单作业调度时限 3 小时，提交到退出另有 6 小时上限。

各 rank 的 processing/MPI 区间分别取最大值，预加载及 MPI 后保存不计入这两个区间。记录完整日志、RAM 峰值、临时读写字节及输出大小。sort/collate 必须日志为 memory mode 且 RAM 临时读写为零；markdup 允许有界延后路径的实际 RAM 临时读写，但重复总数需与 a4 一致。
