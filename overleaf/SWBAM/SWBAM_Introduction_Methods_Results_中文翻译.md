## 1 引言（Introduction）

高通量测序数据的快速增长持续增加了基因组数据分析的计算和输入输出需求。[^amarasinghe2020opportunities][^goodwin2016coming][^schmidt2017ngs]
序列比对后，产生的数据通常以 SAM（Sequence Alignment/Map）格式或其二进制对应格式 BAM（Binary Alignment/Map）存储。[^li2009samtools]
这些文件在用于变异检测等下游分析之前，会经过一系列处理操作，包括统计、过滤、格式转换、排序、配对信息更新和重复标记。
因此，在典型的分析流程中，大型 BAM 文件可能被多次读取、重组和重写。
随着测序数据集持续增长，高效的 BAM 和 SAM 处理对于维持大规模基因组分析的吞吐量变得越来越重要。

SAMtools 和 HTSlib 为 BAM 和 SAM 处理提供了广泛使用的软件基础设施，支持格式转换、排序、索引和重复标记等操作。[^danecek2021samtools][^bonfield2021htslib]
一些工具进一步提高了特定 BAM 操作的性能。
Sambamba 对常见的比对文件操作采用多线程处理，[^tarasov2015sambamba] 而 quickBAM 为已排序且已建立索引的 BAM 文件提供并行访问。[^pitman2023quickbam]
我们此前的工作 RabbitBAM 专注于多核 CPU 平台上的通用 BAM 输入输出，并通过预解析、并行解析、内存池和无锁队列提高并行效率。[^yan2025rabbitbam]
这些工作表明了并行处理在加速 BAM 操作方面的潜力。
然而，现有方法并未直接解决如何高效利用异构众核体系结构，或如何跨分布式处理单元协调执行多种 BAM 操作。

新一代神威平台通过其异构众核体系结构提供了丰富的计算资源。
SW26010-Pro 处理器由多个核组（Core Group，CG）组成，每个核组集成一个管理处理单元（Management Processing Element，MPE）和 64 个计算处理单元（Compute Processing Element，CPE）。
CPE 组织为一个 8 × 8 阵列，每个 CPE 配备 256 KB 的局部数据存储器（Local Data Memory，LDM）。
硬件支持的直接内存访问（Direct Memory Access，DMA）促进 MPE 与 CPE 之间的数据传输，而远程内存访问（Remote Memory Access，RMA）支持 CPE 之间的高效数据交换。[^zhu2021sunway]
这一体系结构提供了互补的并行机会：CPE 阵列可以加速 BGZF 解压、记录解析、序列化和压缩等计算密集型操作，而基于 DMA 的数据移动支持主存与 CPE 局部存储器之间面向批次的执行。
此外，多个核组可以通过 MPI 协作，为大型 BAM 数据集的分布式处理提供基础。
SWQC 和 SWBWA 等已有应用已经表明，在这一体系结构上重新设计生物信息学流程，以利用 CPE 级并行性和 MPE-CPE 协作，是有效的。[^yan2025swqc][^yan2026swbwa]
尽管如此，高效支持通用 BAM 处理仍面临挑战，因为它不仅涉及数据并行的输入输出操作，还涉及应用特定的依赖以及分布式进程间的协调。

神威上的高效 BAM 处理面临三个主要挑战。
首先，传统 BAM 库提供面向记录的接口，而细粒度 CPE 任务分派引入了过多的调度和同步开销。
因此，高效执行需要批次级并行性和协调的 MPE-CPE 执行。
其次，分布式处理需要可扩展的输入划分和输出组织，使多个 MPI rank 能够处理独立的数据区域并生成全局有效的输出，而不集中记录载荷。
第三，BAM 操作具有不同的数据依赖：统计和过滤在很大程度上是批次独立的，而排序需要全局排序，归组和 fixmate 涉及基于 QNAME 的分组，重复标记则需要跨批次和 rank 的按坐标有序的状态管理。
这些差异使统一的并行化策略难以实现。
为应对这些挑战，我们开发了 SWBAM，这是一个面向神威众核平台的高性能 BAM/SAM 处理框架。
SWBAM 提供四条用于 BAM/SAM 读写的基于批次的 MPE-CPE 流水线，以及可复用的输入输出、批次管理、调度和输出组件。
它还提供用于 BGZF 压缩和解压、BAM/SAM 解析和格式化以及记录序列化的优化 CPE 内核。
一项关键设计原则是将批次边界处的流水线灵活性与高效的记录级执行结合：流水线在批次级组合，而性能关键的记录操作在 CPE 内核中静态融合。
例如，BGZF 解压、BAM 解析以及记录级统计或过滤可以在一次 CPE 启动中执行，避免逐记录分派和不必要的中间处理。
MPE 侧批次处理连接这些流水线，以支持不同的输入输出组合。
在该库之上，我们实现了统计、过滤和 BAM/SAM 转换等流式操作，以及用于坐标排序、归组、fixmate 和重复标记的分布式应用。
这些应用包含操作特定的数据重分布和跨 rank 协调。
特别地，重复标记采用带有滑动窗口、边界处理和增量输出的单遍坐标流式算法。
这些分布式应用进一步集成为完整的四阶段去重流程。

本文的主要贡献如下：

- 我们设计了 SWBAM，这是一个面向异构神威众核体系结构的可复用 BAM/SAM 处理框架，提供四条基于批次的 MPE-CPE 流水线和公共处理组件。
- 我们开发了优化的 CPE 内核和面向批次的执行模型，将流水线组合与记录级操作的静态融合结合，从而减少细粒度调度和中间处理开销。
- 我们实现了坐标排序、归组、fixmate 和重复标记等分布式 BAM 应用，并将其集成为完整的去重流程。我们在神威平台上从库、应用和流程三个层面评估该框架。

## 2 方法（Methods）

### 2.1 概述

如图 1 所示，SWBAM 由一个库和一组使用其处理组件的应用组成。
该库提供用于输入划分和分布式输出的公共 BAM/SAM 输入输出组件。
它还提供四条基于批次的流水线，用于 BAM 读取、BAM 写入、SAM 读取和 SAM 写入。
这些流水线通过缓冲区复用和双缓冲协调 MPE-CPE 执行。
MPE 侧的批次后处理连接处理阶段，而批次级算子定义任务特定的操作。
在适当情况下，记录级操作在 CPE 内核中组合。
CPE 内核优化进一步减少 BGZF 压缩和解压、BAM/SAM 解析和格式化以及记录序列化中的分配和数据移动开销。
这些优化包括编解码器复用、可复用的记录缓冲区和融合处理。

SWBAM 应用复用库的处理组件，并为其特定的数据依赖实现算法。
流式应用组合相关的流水线和算子，用于统计、过滤和 BAM/SAM 转换。
分布式应用复用 BAM 读写流水线，而应用特定算法和 MPI 通信处理记录重排及跨 rank 状态。
排序和归组分别依据坐标和 QNAME 重分布记录。
Fixmate 处理跨越批次和 rank 边界的 QNAME 组，而重复标记维护按坐标有序的候选窗口，并协调跨 rank 的重复判定。
这些操作被组合成四阶段去重流程：归组、fixmate、坐标排序和重复标记。

### 2.2 SWBAM 库设计

#### 2.2.1 BAM/SAM 输入输出

SWBAM 提供可复用的 BAM/SAM 输入输出组件，使应用无需单独实现数据访问。
应用可以使用相同的处理流水线和不同的输入输出方式。
对于 BAM 输入，SWBAM 将 BGZF 块划分为连续区间，并将每个区间分配给一个 MPI rank。
根 rank 扫描数据区域，并构建包含块偏移和压缩大小的有序索引。
它将压缩数据读入一个 8 MiB 缓冲区，并在内存中检查连续的 BGZF 头，从而减少块边界检测期间的小规模文件读取。
随后，根 rank 将索引广播给所有 rank。
这些块被划分为块数近似相等的连续区间。
在处理期间，每个 rank 仅通过 POSIX 或 MPI-IO 读取分配给自己的块。
在每个连续批次内，BGZF 块被直接读入用于 CPE 处理的独立目标缓冲区。
POSIX 路径使用 `preadv` 将一个连续文件区域读入缓冲区列表。
MPI-IO 路径使用派生数据类型，将每个块放入其对应的目标缓冲区。
这两条路径都避免了中间缓冲区及随后对各个块的复制。
对于 SAM 输入，SWBAM 将文件头之后的文本划分为近似相等的字节区间。
它将分区边界调整到行尾，使每条记录在单个 rank 内保持完整。
每个 rank 通过 POSIX 或 MPI-IO 读取分配给自己的区间。

SWBAM 分两个阶段写出分布式输出，因为每个 rank 产生的数据量不同。
每个 rank 首先将其输出正文追加到位于内存或临时文件中的本地存储。
在自动模式下，当一次追加将超过内存限制时，该存储切换到临时文件。
处理完成后，各 rank 交换正文大小，并使用前缀和按 rank 顺序计算文件偏移。
每个偏移由文件头大小和在其之前的所有 rank 的输出大小确定。
在 MPI-IO 模式下，每个 rank 通过固定大小的缓冲区读取其暂存正文，并将其写入分配的文件区域。
这避免了在根 rank 上收集完整的输出正文，并限制了最终写出期间的内存使用。
BAM 输出由一个文件头、按 rank 顺序排列的各 rank 本地压缩正文，以及一个 BGZF EOF 块组成。
SAM 输出由一个文本文件头及其后的各 rank 本地文本正文组成。
基于文件的暂存使 SWBAM 能够处理大于可用暂存内存的输出，而无需将整个输出保留在内存中。

#### 2.2.2 基于批次的 MPE-CPE 流水线

SWBAM 提供四条基于批次的 MPE-CPE 流水线，用于 BAM 读取、BAM 写入、SAM 读取和 SAM 写入。
基于批次的执行减少了逐记录处理所涉及的内核启动和同步开销。
MPE 准备输入批次并管理任务执行，而 CPE 执行相应的处理内核。

BAM 读流水线处理压缩 BGZF 块批次。
CPE 解压这些块，并在需要时解析 BAM 记录或执行应用特定操作。
BAM 写流水线接收未压缩数据块或 BAM 记录批次。
CPE 直接压缩输入块，或在压缩前序列化记录。
这两条流水线产生或消费 BGZF 块批次，并支持 rank 本地数据处理。
SAM 读流水线将 rank 本地 SAM 文本转换为 `bam1_t` 记录批次。
MPE 将文本划分为与记录边界对齐的文本块。
CPE 首先复制文本并统计记录数，然后在独立内核中解析 SAM 字段。
SAM 写流水线将 `bam1_t` 记录批次转换为 SAM 文本。
CPE 将记录格式化到独立文本缓冲区中，MPE 按记录顺序追加结果。

SWBAM 使用交替缓冲区，使 MPE 侧工作与 CPE 执行重叠，如图 1 中的 BAM 读取调度所示。
对于 BAM 读取，当 CPE 处理当前批次时，MPE 读取下一个压缩批次。
对于 BAM 写入，当 CPE 压缩当前批次时，MPE 写出前一个压缩批次。
SAM 处理根据流水线阶段和数据依赖采用类似的重叠。
这些策略减少空闲时间，并跨批次复用已分配的缓冲区，而无需在同一个核组内并发执行多个 CPE 内核。

#### 2.2.3 流水线组合与算子

SWBAM 在两个层次组合处理：CPE 内核中的记录级操作，以及通过 MPE 侧后处理连接的批次级阶段。
这种设计复用公共流水线机制，同时允许应用组合不同操作，而不引入逐记录的分派开销。
流水线运行时系统管理批次缓冲区、启动并等待 CPE 内核完成，并调用 MPE 侧钩子。
对于每个批次，MPE 侧算子提供内核入口和任务特定参数、绑定数据缓冲区、验证结果，并执行批次级后处理。
这些算子每个批次调用一次，而不是每条记录调用一次。

在 CPE 内核中，SWBAM 将公共 BAM 记录遍历与任务特定操作结合，包括记录计数、标志统计、基础统计、过滤和直通处理。
C++ 模板在编译内核时确定记录操作。
在运行时，MPE 从预先构建的内核中选择，并传入过滤参数等任务特定选项。
记录遍历直接调用选定的操作，避免逐记录的虚函数或函数指针分派。

批次级组合在内核完成并通过结果验证后，通过 MPE 侧后处理连接流水线。
对于记录计数，BAM 读流水线将记录解析为可复用的 `bam1_t` 对象，MPE 汇总各块的计数。
对于 BAM 到 BAM 处理，MPE 将保留的记录组织为 BGZF 打包计划，并将其提交给 BAM 写流水线进行序列化和压缩。
这些计划引用现有记录，不复制记录载荷或转移所有权。
BAM 到 SAM 和 SAM 到 BAM 处理以类似方式连接相应的读写流水线。

SWBAM 还定义流水线阶段之间的数据所有权和生命周期。
流水线拥有的数据仅在其缓冲区被复用或释放之前有效。
在 BAM 到 BAM 处理中，已解析记录保留在读算子的存储中，直到下游写调用完成对这些记录的消费。
写调用在返回前完成序列化和压缩，但压缩输出仍可能保留在缓冲区中，等待后续写出。
跨批次保留数据的应用通过其算子或算法特定存储管理这些数据的生命周期，并在需要时复制数据或将内核输出写入生命周期更长的存储。

#### 2.2.4 CPE 内核优化

SWBAM 优化 CPE 内核，以减少重复分配、压缩开销和中间数据移动。
它复用编解码器对象和工作缓冲区，并在一次内核执行中结合相关处理步骤。

SWBAM 跨内核启动复用 libdeflate 压缩器和解压器对象。
每个 CPE 在首次使用时创建解压器，并将其复用于后续块。
压缩器按压缩级别缓存，并仅在所需级别变化时重新创建。
对于级别 1 压缩，SWBAM 在每个搜索位置检查一个哈希表候选，以减少匹配搜索工作量。
对于足够长的匹配，哈希更新覆盖前六个内部位置，随后采用两字节步长。
这些改动减少候选检查和哈希表更新，同时保留有效的 DEFLATE 和 BGZF 输出。
对于 BAM 输入，SWBAM 在一个 CPE 内核中结合解压、解析和记录处理。
解码块被直接处理，这些操作之间不需要单独的内核启动或 MPE 侧处理阶段。
统计内核在每个 CPE 上复用一个临时 `bam1_t` 记录及其数据缓冲区。
BAM 变换内核则将解析后的记录存入跨批次复用的预分配内存区，从而减少逐记录分配。
对于 BAM 输出，SWBAM 在一个 CPE 内核中结合记录序列化和 BGZF 压缩。
每个 CPE 将打包计划指定的记录序列化到可复用的未压缩 BGZF 载荷缓冲区中，并直接压缩该载荷。
这避免了序列化和压缩之间的中间载荷复制及单独的内核启动。
当直接提供已序列化的 BAM 载荷时，内核跳过记录序列化，并压缩输入字节。
压缩输出缓冲区也跨批次复用。

SWBAM 也在 SAM 处理中复用缓冲区。
快速 SAM 解析器将记录写入各文本块的内存区，并在每个文本块内缓存最近的参考序列名称查找结果。
快速解析器无法处理的记录由通用解析器处理。
对于 SAM 输出，每个 CPE 直接将记录格式化到其批次文本缓冲区中，而不是为每条记录创建单独的字符串。
MPE 在格式化之前预留缓冲区容量，并将扩容后的缓冲区保留供后续批次使用。
这些优化减少了 SAM 解析和格式化中的重复分配和中间数据处理。

### 2.3 基于 SWBAM 库构建的应用

#### 2.3.1 流式 BAM 处理

SWBAM 提供用于统计、过滤、重写和格式转换的流式 BAM/SAM 操作。
这些操作按输入顺序处理记录，不进行全局记录重排，使每个 MPI rank 能够独立处理分配给自己的输入区间。
对于 BAM 输入，记录处理在构建块区间索引的独立 BGZF 扫描之后进行。

标志统计使用 BAM 读流水线，并在批次和 rank 两个层次汇总结果。
CPE 更新独立的计数数组，MPE 侧的 flagstat 算子在每个批次之后，将这些计数合并到 rank 本地总计中。
MPI 求和归约在根 rank 上合并各 rank 的本地总计，以生成最终报告。
该操作不生成输出 BAM 数据流。
BAM 过滤和重写通过 MPE 侧变换算子连接 BAM 读写流水线。
算子根据请求的选项选择过滤或直通 CPE 内核。
每个批次之后，MPE 后处理将保留记录的引用组织为满足 BGZF 载荷大小限制的打包计划。
BAM 写流水线消费这些计划，并将生成的压缩块追加到各 rank 的本地输出正文。
记录在每个 rank 内保持其输入顺序，最终文件按输入区间顺序放置各 rank 本地正文，而不按坐标或 QNAME 排序。
格式转换将输入格式的读流水线连接到输出格式的写流水线。
对于 BAM 到 SAM 转换，MPE 侧转换算子将解析后的 BAM 记录引用传给 SAM 写流水线。
对于 SAM 到 BAM 转换，MPE 后处理从解析后的 SAM 记录构建打包计划，并将其提交给 BAM 写流水线。
中间记录保持有效，直到下游流水线完成对它们的消费，使两条流水线能够按批次运行，而无需额外的记录级分派层。

这些流式操作在输入划分后只需要少量 rank 间通信，因为记录处理仍在各 rank 本地进行。
相比之下，下面描述的分布式算法需要记录重分布或跨 rank 状态。

#### 2.3.2 分布式 BAM 处理

SWBAM 实现需要全局记录重组或跨记录状态的分布式 BAM 操作。
排序建立全局坐标顺序，而归组按 QNAME 对记录分组。
Fixmate 为完整的 QNAME 组更新配对信息，重复标记则跨批次和 MPI rank 边界比较候选。
这些应用复用公共 BAM 读写流水线，而应用特定算法管理记录重分布、边界处理和跨 rank 状态。

CPE 提取坐标键和原始 BAM 记录，而 MPE 对本地元数据排序，并从有序记录中选取样本。
根 rank 收集样本、确定全局分割点，并广播这些分割点，以定义各 MPI rank 的坐标区间。
随后，根据这些分割点交换记录。
由于接收的数据段分别有序，每个 rank 执行 $k$ 路归并，而不是再次对所有接收记录排序。
归并后的原始记录被打包为 BGZF 载荷，并通过公共 BAM 写流水线压缩。
归组使用基于 QNAME 的划分，而不是构建全局坐标顺序。
CPE 提取 QNAME 哈希、记录元数据和原始 BAM 记录。
每个哈希被分配到一个桶，每个桶映射到一个归属 rank，使相同 QNAME 的记录到达同一个 rank。
本地排序后，每个 rank 保留归属于自身的记录，并以有界数据块交换其余记录。
接收 rank 按桶、哈希和完整 QNAME 归并数据段，将同一 QNAME 的记录分组在一起，而不施加全局 QNAME 字典序。
在每组内，记录按 READ1/READ2 标志位排序，然后按原始输入顺序排序。
与 SAMtools 的标准临时分桶流程不同，SWBAM 同时支持内存归组和外存归组。[^danecek2021samtools]
排序也支持内存和外存执行。
在外存模式下，SWBAM 在配置的内存限制下生成有序段，并执行有界数据交换和流式多路归并。

归并扇入 $F$ 限制每一遍处理的输入段数；在最终归并和压缩之前，必要时执行额外的归并遍数（图 2（c））。

Fixmate 为相同 QNAME 的记录更新配对信息。
BAM 读流水线提供来自按名称归组输入的记录，MPE 按 QNAME 对连续记录分组。
跨越批次边界的组被保留，直到后续批次补全它们。
rank 本地的第一个和最后一个组也被延后处理，因为它们可能跨越 MPI rank 边界。
各 rank 交换边界 QNAME 信息，以确定组的归属，并将相应的组片段传送到其归属 rank。
对于每个完整组，CPE 规划内核确定所需的配对字段和标签更新，并计算输出大小。
MPE 根据规划的记录长度计算输出偏移，第二个 CPE 内核将记录重写到互不重叠的输出区域。
支持的更新包括配对坐标、标志、模板长度，以及 `MQ`、`MC` 和 `ms` 标签。
随后，重写后的记录通过公共 BAM 写流水线序列化和压缩。
边界和内部输出段按 QNAME 组顺序组合。

$$

其中，$p_r$ 是 rank $r$ 上已处理的比对起点坐标，$L$ 是配置的最大读长上界。

算法 1 概括处理和输出流程。

**算法 1：rank r 上的分布式重复标记**

输入：rank 本地按坐标排序的 BAM 块；最大读长 `L`。

输出：rank 本地已进行重复标记的 BGZF 正文。

```text
P_r <- 探测 rank 两端(r, 32)
G <- 收集 rank 起始坐标(P_r)
H_r <- 构建边界计划(P_r, G, L)                // 仅当所有 rank 边界均被覆盖时启用预计算
初始化归属窗口 W_r、待处理块 Q_r 和有序输出 O_r
T <- 全归约取最大值(本地批次数)
对于 t = 1, ..., T：
    (B_r, C_r, p_r) <- 解码并提取批次(t)
    启动已准备的压缩()
    C_r <- 捕获并应用计划(B_r, C_r, Q_r, H_r)
    如果 H_r 未启用：
        S <- 全收集进度和 EOF 信息(p_r)
    结束如果
    C_r_owner <- 按归属 rank 交换(C_r, G, Q_r)
    D_r <- 更新归属窗口(W_r, C_r_owner, p_r, L, Q_r)
    如果 H_r 未启用：
        将 安全释放边界(W_r, G, S, L) 的结果加入 D_r
    结束如果
    路由并应用判定(D_r, Q_r)
    完成并准备输出(Q_r, O_r)
结束循环
验证跨 rank 的坐标顺序
D_r <- 将归属窗口中的胜出候选最终确定为 KEEP(W_r, Q_r)
路由并应用判定(D_r, Q_r)
检查不存在仍为待定状态的源记录判定
完成剩余压缩，并按输入块和片段顺序封存 O_r
```

边界处理保留候选，直到所需的跨 rank 比较完成。
SWBAM 在 rank 区间两端各探测最多 32 个 BGZF 块，并且仅在所有 rank 的探测均覆盖所需 halo 时启用边界预计算。
如果覆盖不足，保守边界窗口将保持活跃，直到相关 rank 推进到边界坐标加 $2L$ 之后，或耗尽其输入。
在这条回退路径中，各 rank 交换进度和 EOF 信息，使边界候选仅在不可能再有相关远程候选时被释放。
在每一轮处理中，当前批次的候选先被交换和处理，然后才进行安全的边界释放。
提前完成的 rank 继续以空批次参与集体通信轮次。
等待远程判定的记录在本地 EOF 之后仍保持待定状态，直到其归属 rank 的判定到达。
只有重复判定全部解决的块才进入压缩。
压缩可能乱序完成，但压缩片段按输入块和块内位置建立索引，以保留最终的逻辑顺序。
解码缓冲区在活跃压缩使用它们期间保持有效；未解决的块可以在缓存压力下临时暂存。
公共库管理批次执行和压缩，而应用维护滑动窗口、边界状态、MPI 判定、待处理块和输出顺序元数据。

#### 2.3.3 去重流程

SWBAM 将归组、fixmate、坐标排序和重复标记组合为端到端去重流程。
这些阶段按此顺序运行，因为 fixmate 要求将相同 QNAME 的记录分组在一起，而重复标记要求更新后的配对信息和按坐标排序的输入。
该流程首先通过归组按 QNAME 对记录分组，然后运行启用配对得分计算的 fixmate，按基因组坐标对更新后的记录排序，最后标记重复。
每个阶段使用相应的分布式 SWBAM 应用和公共 BAM 输入输出接口。
每个阶段的输出写入中间 BAM 文件，并传给下一阶段。
该流程在生成最终重复标记 BAM 文件之前，产生归组后、fixmate 更新后和坐标排序后的中间文件。
中间文件可以在使用后自动移除，也可以保留用于调试和验证。
内存限制和压缩设置被传递给相关阶段，而排序和归组在需要时可以使用其外存实现。

D1–D3 上的峰值只读吞吐量分别为 15.65、13.17 和 15.26 百万条记录每秒，而读写吞吐量达到 5.68、4.82 和 5.79 百万条记录每秒。

只读处理中线程数较高的最优点出现在相对平坦的曲线上，表明收益递减。

SWBAM 从一个到十二个活跃核组表现出近线性扩展，只读处理的加速比为 10.77–10.90 倍，读写处理为 11.54–11.58 倍，分别对应约 90% 和 96% 的并行效率。
这种扩展性来自 rank 本地处理、CPE 级块并行以及 MPE-CPE 重叠的结合。
根 rank 将 BGZF 块索引划分为均衡、连续的输入区间，使每个 rank 能够独立处理分配给自己的块。
在每个 rank 内，双缓冲使 MPE 侧输入读取与 CPE 执行重叠，同时避免 rank 之间的记录级通信。
在十二个核组下，D1–D3 的只读吞吐量分别达到 128.59、95.93 和 122.85 百万条记录每秒。
读写处理的吞吐量低于只读处理，因为它额外需要记录打包、序列化、压缩和输出组装。
尽管如此，它仍保持约 96% 的并行效率。
打包和压缩仍在 rank 本地进行，而双缓冲使一个批次的输出与下一个批次的处理重叠。
在最终组装期间，各 rank 交换正文大小，以确定输出偏移，而不是传输记录载荷。
这种基于元数据的协调避免了 rank 间的记录移动，并有助于保持完整写入路径的扩展性。
在十二个核组下，D1–D3 的读写吞吐量分别达到 37.83、26.23 和 36.05 百万条记录每秒。

在六个神威节点上使用六个活跃核组时，SWBAM 在每个数据集和模式下的吞吐量都高于最佳已测 SAMtools 配置。
这一优势反映了 SWBAM 跨 CPE 的分布式记录处理，与之相比，SAMtools 在主线程上遍历记录，并使用工作线程处理 BGZF。
由此得到的吞吐量比值在只读处理中为 3.82–4.35 倍，在读写处理中为 2.77–3.41 倍。

MPI 初始化和结束对短时执行产生显著开销。
对于十二个节点上的 D1 只读处理，十二个核组下的处理时间中位数为 1.38 秒，而完整 MPI 区间为 8.53 秒。
因此，所报告的扩展性描述的是处理阶段，而完整执行时间还包括 MPI 启动和关闭开销。

#### 3.3.1 流式 BAM 处理

SWBAM 在四项流式操作中实现了 2.80–5.62 倍的加速比（表 3），其中 BAM 到 SAM 转换的收益最大。
性能差异主要反映了记录处理能够分布到各 rank 和 CPE 的程度，以及记录输出引入的额外成本。

标志统计实现了 3.15–3.46 倍的加速比，受益于 CPE 上并行执行的 BGZF 解码、记录解析和标志累计，而 SAMtools 在其主线程上保留记录遍历和计数器更新。
MAPQ 过滤实现了较低的 2.80–3.33 倍加速比，因为与标志统计不同，它要求对保留记录进行序列化和 BGZF 压缩。
由于 81.28%–95.82% 的输入记录通过过滤阈值，仍保留了大量输出处理工作。
尽管两种实现都并行执行 BGZF 压缩，SWBAM 还额外进行记录打包和最终输出组装，从而降低了其相对于统计工作负载的优势。
BAM 到 SAM 实现了最高的加速比，范围为 5.13–5.62 倍。
这一优势来自将完整的记录处理路径分布到六个 rank，其中 CPE 通过批次级记录指针交接执行记录构建和并行 SAM 格式化。
SAMtools 也并行执行 SAM 格式化，但保留主线程上的记录遍历及向有序输出分发器的提交。
因此，由此获得的优势反映了完整转换流水线在组织方式上的差异，而不仅仅是格式化并行性的差异。
SAM 到 BAM 在 D1、D2 和 D3 上分别实现了 3.10 倍、3.63 倍和 3.44 倍的加速比。
两种实现都并行执行 SAM 解析和 BGZF 压缩。
SWBAM 将解析和压缩分布到各 rank 本地的 CPE 流水线，而 SAMtools 使用共享工作线程池，但保留主线程上的记录提交和 BAM 序列化。

#### 3.3.2 分布式 BAM 处理

在四项分布式操作中，SWBAM 相对于 SAMtools 实现了 1.28–3.52 倍的加速比。
坐标排序最稳定地获益，而重复标记表现出最强的数据集依赖。
这些差异反映了每项操作的记录处理工作负载能够被有效分布的程度，以及执行路径上仍保留多少顺序处理或状态管理工作。

坐标排序实现了 3.25–3.52 倍的加速比。
尽管 SAMtools 并行执行基数排序和 BGZF 输入输出，其主线程仍将记录装入共享内存区，并推进最终的堆归并。
SWBAM 将记录提取、本地排序、坐标划分和区间本地归并分布到六个 rank，而 CPE 处理 BGZF 块。
它还在保留原始 BAM 载荷的同时，对紧凑的坐标元数据排序，从而避免为每条存储记录构造独立的 `bam1_t` 对象。
因此，其优势来自将更多端到端重排流水线工作分布执行并减少记录表示开销，而不是来自更快的本地排序算法。
归组实现了较小的 2.72–2.88 倍加速比。
SAMtools 将记录写入压缩的临时桶，随后在主线程上装入每个桶并对其排序。
SWBAM 将哈希桶分布到各 rank，但 QNAME 比较和载荷打包仍需要 MPE 侧处理。
对于 D1 和 D3 上的归组，SWBAM 避免了 SAMtools 临时桶所需的中间 BGZF 编码和解码。
在 D2 上，尽管外部有序段处理增加了中间写入和归并，归组和坐标排序仍分别实现了 2.79 倍和 3.47 倍的加速比。

Fixmate 实现了相对稳定的 2.02–2.09 倍加速比。
SAMtools 在主线程上执行 QNAME 分组和配对字段更新，工作线程主要处理 BGZF 输入输出。
SWBAM 将配对更新规划和记录重写下放到 CPE，但 QNAME 组扫描和输出偏移构建仍在每个 MPE 上进行。
这些剩余的 MPE 侧操作连同输出序列化和压缩，限制了下放配对更新所带来的收益。

重复标记对数据集更为敏感，其加速比从 D1 上的 2.84 倍降至 D2 上的 1.82 倍和 D3 上的 1.28 倍。
与随着记录处理而更新持久哈希表的 SAMtools 不同，SWBAM 按批次处理候选，并将未决候选保留到后续批次，直到足够的坐标推进允许最终确定它们。
这提供了批次级并行性，但也使性能对保留状态的数量和边界协调敏感。
相应地，SAMtools 保持相对稳定的每条记录 0.79–0.83 微秒的处理时间，而 SWBAM 从 D1 上的 0.28 微秒增加到 D2 上的 0.46 微秒和 D3 上的 0.63 微秒。
在 D2 上，较低的加速比主要与不均衡的本地窗口工作负载有关，而不是边界回退。
未决候选的局部集中要求跨批次保留和处理更多状态，从而增加状态管理和缓冲开销。
这体现为最大分组处理时间从 D1 上的约 16.6 秒增加到 D2 上的 56.0 秒，待处理缓冲区大小从 17 MB 增加到 269 MB，而跨 rank 候选交换量从 71.2 kB 降至 6.8 kB。
D3 表现出不同的瓶颈，因为 rank 边界附近密集分布的坐标使固定的 32 块探测无法覆盖所需坐标范围，从而触发边界回退。
由此增加的候选处理和数据暂存导致每轮约 1,560 万次边界候选访问及 594 次原始批次转存，写入并读回 2.39 GB 数据。
这些额外成本解释了 D3 上较低的加速比；尽管如此，SWBAM 相对于 SAMtools 仍实现了 1.28 倍加速，表明其对具有挑战性的坐标分布具有稳健性。

#### 3.3.3 去重流程性能

在所评估的配置中，SWBAM 相对于 SAMtools 实现了 2.37–3.05 倍的流程级加速比（表 5）。
这些结果表明，单项分布式操作的性能收益能够延续到完整的四阶段流程，尽管重复标记限制了整体加速比，尤其是在 D3 上。

重复标记是 D2 和 D3 上加速最少的阶段，分别实现了 1.82 倍和 1.28 倍的加速比。
其基于窗口的候选状态管理和边界处理引入了额外的本地处理及缓冲成本，从而减少了更快的归组、fixmate 和排序所带来的收益。
对于 D2，外部有序段流程实现了 2.37 倍加速比。
归组和排序中的额外有序段生成及归并引入了中间处理成本。

完整回读确认了所有 SWBAM 流程运行的记录数和坐标顺序。
总体而言，结果表明，SWBAM 在包含外部有序段处理的完整分布式 BAM 操作序列中保持显著性能优势，同时也表明重复标记是进一步优化的主要目标。
