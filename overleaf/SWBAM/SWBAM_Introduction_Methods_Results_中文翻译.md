## 摘要（Abstract）

BAM/SAM 文件处理是高通量测序数据分析的重要组成部分。
测序数据集的持续增长增加了这些操作的计算和输入输出需求，使高效且可扩展的处理面临越来越大的挑战。
尽管神威异构众核体系结构为加速 BAM/SAM 处理提供了丰富的计算资源，利用这一体系结构的专用库和应用仍然缺乏。
我们提出 SWBAM，这是一个用于在神威异构众核体系结构上快速且可扩展地处理 BAM/SAM 的库和应用套件。
该库提供一组用于 BAM/SAM 处理的通用组件，包括用于输入划分和分布式输出的输入输出组件，以及四条可复用的 MPE-CPE 流水线，用于面向批次的 BAM/SAM 读写。
基于该库，SWBAM 既实现了 rank 本地的 BAM/SAM 操作，也实现了需要全局排序或跨 rank 协调的操作。
后者被集成为一个端到端去重流程。
在来自人类和小鼠的三个测序数据集上，SWBAM 的 BAM 输入输出库从 1 个核组（CG）扩展到 12 个核组时，在不包括 MPI 初始化和结束的处理区间内测得 90%–96% 的并行效率。
与运行在一台 128 核 x86 服务器上的 SAMtools 相比，在单个神威节点上使用六个核组的 SWBAM 对这两类操作分别实现了 1.03–4.61 倍和 1.33–3.32 倍的端到端加速，对完整去重流程实现了 2.27–2.70 倍加速。
SWBAM 可在 `https://github.com/WWWZZSS/SWBAM` 免费获取。

**关键词：** BAM/SAM 处理，异构众核体系结构，神威，分布式处理，高性能计算，基因组数据处理。

## 1 引言（Introduction）

高通量测序数据的快速增长持续增加了基因组数据分析的计算和输入输出需求。[^amarasinghe2020opportunities][^goodwin2016coming][^schmidt2017ngs]
序列比对后，产生的数据通常以 SAM（Sequence Alignment/Map）格式或其二进制对应格式 BAM（Binary Alignment/Map）存储。[^li2009samtools]
这些文件在用于变异检测等下游分析之前，会经过一系列处理操作，包括统计、过滤、格式转换、排序、配对信息更新和重复标记。
因此，在典型的分析流程中，大型 BAM 文件可能被多次读取、重组和重写。
随着测序数据集持续增长，高效的 BAM 和 SAM 处理对于维持大规模基因组分析的吞吐量变得越来越重要。

SAMtools 和 HTSlib 为 BAM 和 SAM 处理提供了广泛使用的软件基础设施，支持格式转换、排序、索引和重复标记等操作。[^danecek2021samtools][^bonfield2021htslib]
一些工具进一步提高了特定 BAM 操作的性能。
Sambamba 对常见的比对文件操作采用多线程处理，[^tarasov2015sambamba] 而 quickBAM 为已排序且已建立索引的 BAM 文件提供并行访问。[^pitman2023quickbam]
RabbitBAM 专注于多核 CPU 平台上的通用 BAM 输入输出，并通过预解析、并行解析、内存池和无锁队列提高并行效率。[^yan2025rabbitbam]
这些工作表明了并行处理在加速 BAM 操作方面的潜力。
然而，现有方法并未直接解决如何高效利用异构众核体系结构，或如何跨分布式处理单元协调执行多种 BAM 操作。

新一代神威平台通过其异构众核体系结构提供了丰富的计算资源。
SW26010-Pro 处理器由多个核组（Core Group，CG）组成，每个核组集成一个管理处理单元（Management Processing Element，MPE）和 64 个计算处理单元（Compute Processing Element，CPE）。
CPE 组织为一个 8 × 8 阵列，每个 CPE 配备 256 KB 的局部数据存储器（Local Data Memory，LDM）。
硬件支持的直接内存访问（Direct Memory Access，DMA）促进 MPE 与 CPE 之间的数据传输，而远程内存访问（Remote Memory Access，RMA）支持 CPE 之间的高效数据交换。[^zhu2021sunway]
这一体系结构提供了互补的并行机会：CPE 阵列可以加速分块 GNU Zip 格式（Blocked GNU Zip Format，BGZF）解压、记录解析、序列化和压缩等计算密集型操作，而基于 DMA 的数据移动支持 MPE 主存与 CPE 局部存储器之间面向批次的执行。
此外，多个核组可以通过 MPI 协作，为大型 BAM 数据集的分布式处理提供基础。
SWQC 和 SWBWA 等已有应用已经表明，在这一体系结构上重新设计生物信息学流程，以利用 CPE 级并行性和 MPE-CPE 协作，是有效的。[^yan2025swqc][^yan2026swbwa]
尽管如此，高效支持通用 BAM 处理仍面临挑战，因为它不仅涉及数据并行的输入输出操作，还涉及应用特定的依赖以及分布式进程间的协调。

神威上的高效 BAM 处理面临三个主要挑战。
首先，传统 BAM 库提供面向记录的接口，而细粒度 CPE 任务分派引入了过多的调度和同步开销。
因此，高效执行需要批次级并行性和协调的 MPE-CPE 执行。
其次，分布式处理需要可扩展的输入划分和输出组织，使各 MPI rank 能够处理分配给自己的输入区域，并共同生成全局有效的输出，而无需将全部记录载荷收集到单个 rank 上。
第三，BAM 操作具有不同的数据依赖：统计和过滤在很大程度上是批次独立的，而排序需要全局排序，归组和 fixmate 涉及基于 QNAME 的分组，重复标记则需要跨批次和 rank 的按坐标有序的状态管理。
这些差异使统一的并行化策略难以实现。
为应对这些挑战，我们开发了 SWBAM，这是一个面向神威众核平台的高性能 BAM/SAM 处理框架。
SWBAM 提供四条用于 BAM/SAM 读写的基于批次的 MPE-CPE 流水线，以及可复用的输入输出、批次管理、调度和输出组件。
它还提供用于 BGZF 压缩和解压、BAM/SAM 解析和格式化以及记录序列化的优化 CPE 内核。
一项关键设计原则是将批次边界处的流水线灵活性与高效的记录级执行结合：流水线在批次级组合，而性能关键的记录操作在 CPE 内核中静态融合。
例如，BGZF 解压、BAM 解析以及记录级统计或过滤可以在一次 CPE 启动中执行，避免逐记录的运行时算子分派和不必要的中间处理。
MPE 侧批次处理连接这些流水线，以支持不同的输入输出组合。
在该库之上，我们实现了统计、过滤和 BAM/SAM 转换等流式操作，以及用于坐标排序、归组、fixmate 和重复标记的分布式应用。
这些应用包含操作特定的数据重分布和跨 rank 协调。
特别地，重复标记采用带有滑动窗口、边界处理和增量输出的单遍坐标流式算法。
这些分布式应用进一步集成为完整的四阶段去重流程。

本文的主要贡献如下：

- 我们设计了 SWBAM 库，这是一个面向异构神威众核体系结构的可复用 BAM/SAM 处理框架，提供四条基于批次的 MPE-CPE 流水线和公共处理组件。
- 我们开发了优化的 CPE 内核和面向批次的执行模型，将流水线组合与记录级操作的静态融合结合，从而减少细粒度调度和中间处理开销。
- 我们实现了坐标排序、归组、fixmate 和重复标记等分布式 BAM 应用，并将其集成为完整的去重流程。
  我们在神威平台上从库、应用和流程三个层面评估该框架。

## 2 方法（Methods）

### 2.1 概述

如图 1 所示，SWBAM 由一个库和一组使用其处理组件的应用组成。
该库提供用于输入划分和分布式输出的公共 BAM/SAM 输入输出组件。
它还提供四条基于批次的流水线，用于 BAM 读取、BAM 写入、SAM 读取和 SAM 写入。
这些流水线通过缓冲区复用和双缓冲协调 MPE-CPE 执行。
MPE 侧的批次后处理连接处理阶段，而批次级算子定义任务特定的操作。
在适当情况下，记录级操作在 CPE 内核中组合。
CPE 内核优化进一步减少 BGZF 压缩和解压、BAM/SAM 解析和格式化以及记录序列化中的分配和数据移动开销。
这些优化包括编解码器复用、可复用的记录缓冲区和融合处理。

SWBAM 应用复用库的处理组件，并为其特定的数据依赖实现算法。
流式应用组合相关的流水线和算子，用于统计、过滤和 BAM/SAM 转换。

排序和归组分别依据坐标和 QNAME 重分布记录。

### 2.2 SWBAM 库设计

#### 2.2.1 BAM/SAM 输入输出

SWBAM 提供可复用的 BAM/SAM 输入输出组件，使应用无需单独实现数据访问。
应用可以使用相同的处理流水线和不同的输入输出方式。
对于 BAM 输入，SWBAM 将 BGZF 块划分为连续区间，并将每个区间分配给一个 MPI rank。
根 rank 扫描数据区域，并构建包含块偏移和压缩大小的有序索引。
它将压缩数据读入一个 8 MiB 缓冲区，并在内存中检查连续的 BGZF 头，从而减少块边界检测期间的小规模文件读取。
随后，根 rank 将索引广播给所有 rank。
这些块被划分为块数近似相等的连续区间。
在处理期间，每个 rank 仅通过 POSIX 或 MPI-IO 读取分配给自己的块。
在每个连续批次内，BGZF 块被直接读入用于 CPE 处理的独立目标缓冲区。
POSIX 路径使用 `preadv` 将一个连续文件区域读入缓冲区列表。
MPI-IO 路径使用派生数据类型，将每个块放入其对应的目标缓冲区。
这两条路径都避免了中间缓冲区及随后对各个块的复制。
对于 SAM 输入，SWBAM 将文件头之后的文本划分为近似相等的字节区间。
它将分区边界调整到行尾，使每条记录在单个 rank 内保持完整。
每个 rank 通过 POSIX 或 MPI-IO 读取分配给自己的区间。

SWBAM 分两个阶段写出分布式输出，因为每个 rank 产生的数据量不同。
每个 rank 首先将其输出正文追加到位于内存或临时文件中的本地存储。
在自动模式下，当一次追加将超过内存限制时，该存储切换到临时文件。
处理完成后，各 rank 交换正文大小，并使用前缀和按 rank 顺序计算文件偏移。
每个偏移由文件头大小和在其之前的所有 rank 的输出大小确定。
在 MPI-IO 模式下，每个 rank 通过固定大小的缓冲区读取其暂存正文，并将其写入分配的文件区域。
这避免了在根 rank 上收集完整的输出正文，降低了最终输出生成期间根 rank 的内存需求。
BAM 输出由一个文件头、按 rank 顺序排列的各 rank 本地压缩正文，以及一个 BGZF EOF 块组成。
SAM 输出由一个文本文件头及其后的各 rank 本地文本正文组成。
基于文件的暂存使 SWBAM 能够处理大于可用暂存内存的输出，而无需将整个输出保留在内存中。

#### 2.2.2 基于批次的 MPE-CPE 流水线

SWBAM 提供四条基于批次的 MPE-CPE 流水线，用于 BAM 读取、BAM 写入、SAM 读取和 SAM 写入。
基于批次的执行减少了逐记录处理所涉及的内核启动和同步开销。
MPE 准备输入批次并管理任务执行，而 CPE 执行相应的处理内核。

BAM 读流水线处理压缩 BGZF 块批次。
CPE 解压这些块，并在需要时解析 BAM 记录或执行应用特定操作。
BAM 写流水线接收未压缩数据块或 BAM 记录批次。
CPE 直接压缩输入块，或在压缩前序列化记录。
这两条流水线产生或消费 BGZF 块批次，并支持 rank 本地数据处理。
SAM 读流水线将 rank 本地 SAM 文本转换为 `bam1_t` 记录批次。
MPE 将文本划分为与记录边界对齐的文本块。
CPE 首先复制文本并统计记录数，然后在独立内核中解析 SAM 字段。
SAM 写流水线将 `bam1_t` 记录批次转换为 SAM 文本。
CPE 将记录格式化到独立文本缓冲区中，MPE 按记录顺序追加结果。

SWBAM 使用交替缓冲区，使 MPE 侧工作与 CPE 执行重叠，如图 1 中的 BAM 读取调度所示。
对于 BAM 读取，当 CPE 处理当前批次时，MPE 读取下一个压缩批次。
对于 BAM 写入，当 CPE 压缩当前批次时，MPE 写出前一个压缩批次。
SAM 处理根据流水线阶段和数据依赖采用类似的重叠。
这些策略减少空闲时间，并跨批次复用已分配的缓冲区，而无需在同一个核组内并发执行多个 CPE 内核。

#### 2.2.3 流水线组合与算子

SWBAM 在两个层次组合处理：CPE 内核中的记录级操作，以及通过 MPE 侧后处理连接的批次级阶段。
这种设计复用公共流水线机制，同时允许应用组合不同操作，而不引入逐记录的分派开销。
流水线运行时系统管理批次缓冲区、启动并等待 CPE 内核完成，并调用 MPE 侧钩子。
对于每个批次，MPE 侧算子提供内核入口和任务特定参数、绑定数据缓冲区、验证结果，并执行批次级后处理。
这些算子每个批次调用一次，而不是每条记录调用一次。

在 CPE 内核中，SWBAM 将公共 BAM 记录遍历与任务特定操作结合，包括记录计数、标志统计、过滤和直通处理。
C++ 模板在编译内核时确定记录操作。
在运行时，MPE 从预先构建的内核中选择，并传入过滤参数等任务特定选项。
记录遍历直接调用选定的操作，避免逐记录的虚函数或函数指针分派。

批次级组合在内核完成并通过结果验证后，通过 MPE 侧后处理连接流水线。
对于记录计数，BAM 读流水线将记录解析为可复用的 `bam1_t` 对象，MPE 汇总各块的计数。
对于 BAM 到 BAM 处理，MPE 将保留的记录组织为 BGZF 打包计划，并将其提交给 BAM 写流水线进行序列化和压缩。
这些计划引用现有记录，不复制记录载荷或转移所有权。

SWBAM 还定义流水线阶段之间的数据所有权和生命周期。
流水线拥有的数据仅在其缓冲区被复用或释放之前有效。
在 BAM 到 BAM 处理中，已解析记录保留在读算子的存储中，直到下游写调用完成对这些记录的消费。
写调用在返回前完成序列化和压缩，但压缩输出仍可能保留在缓冲区中，等待后续写出。
跨批次保留数据的应用通过其算子或算法特定存储管理这些数据的生命周期，并在需要时复制数据或将内核输出写入生命周期更长的存储。

#### 2.2.4 CPE 内核优化

SWBAM 优化 CPE 内核，以减少重复分配、压缩开销和中间数据移动。
它复用编解码器对象和工作缓冲区，并在一次内核执行中结合相关处理步骤。

SWBAM 跨内核启动复用 libdeflate 压缩器和解压器对象。
针对神威适配的 libdeflate 实现将这些对象分配在每个 CPE 的局部数据存储器（LDM）中，从而减少压缩和解压过程中的主存访问。
每个 CPE 在首次使用时创建解压器，并将其复用于后续块。
压缩器按压缩级别缓存，并仅在所需级别变化时重新创建。
对于级别 1 压缩，SWBAM 在每个搜索位置检查一个哈希表候选，以减少匹配搜索工作量。
对于足够长的匹配，哈希更新覆盖前六个内部位置，随后采用两字节步长。
这些改动减少候选检查和哈希表更新，同时保留有效的 DEFLATE 和 BGZF 输出。
这项优化牺牲压缩比以换取吞吐量，与原始的级别 1 压缩器相比，压缩 BAM 的大小平均增加 2.82%（D1–D3 的范围为 2.50%–2.99%）。
对于 BAM 输入，SWBAM 在一个 CPE 内核中结合解压、解析和记录处理。
解码块被直接处理，这些操作之间不需要单独的内核启动或 MPE 侧处理阶段。
统计内核在每个 CPE 上复用一个临时 `bam1_t` 记录及其数据缓冲区。
BAM 变换内核则将解析后的记录存入跨批次复用的预分配内存区，从而减少逐记录分配。
对于 BAM 输出，SWBAM 在一个 CPE 内核中结合记录序列化和 BGZF 压缩。
每个 CPE 将打包计划指定的记录序列化到可复用的未压缩 BGZF 载荷缓冲区中，并直接压缩该载荷。
这避免了序列化和压缩之间的中间载荷复制及单独的内核启动。
当直接提供已序列化的 BAM 载荷时，内核跳过记录序列化，并压缩输入字节。
压缩输出缓冲区也跨批次复用。

SWBAM 也在 SAM 处理中复用缓冲区。
快速 SAM 解析器将解析后的记录存储到各文本块的内存区，并在每个文本块内缓存最近的参考序列名称查找结果。
对于 SAM 输出，每个 CPE 直接将记录格式化到其批次文本缓冲区中，而不是为每条记录创建单独的字符串。
MPE 在格式化之前预留缓冲区容量，并将扩容后的缓冲区保留供后续批次使用。
这些优化减少了 SAM 解析和格式化中的重复分配和中间数据处理。

### 2.3 基于 SWBAM 库构建的应用

#### 2.3.1 流式 BAM 处理

SWBAM 提供用于统计、过滤、重写和格式转换的流式 BAM/SAM 操作。
这些操作按输入顺序处理记录，不进行全局记录重排，使每个 MPI rank 能够独立处理分配给自己的输入区间。
对于 BAM 输入，记录处理在构建块区间索引的独立 BGZF 扫描之后进行。

标志统计使用 BAM 读流水线，并在批次和 rank 两个层次汇总结果。
CPE 更新独立的计数数组，MPE 侧的 flagstat 算子在每个批次之后，将这些计数合并到 rank 本地总计中。
MPI 求和归约在根 rank 上合并各 rank 的本地总计，以生成最终报告。
该操作不生成输出 BAM 数据流。
BAM 过滤和重写通过 MPE 侧变换算子连接 BAM 读写流水线。
算子根据请求的选项选择过滤或直通 CPE 内核。
每个批次之后，MPE 后处理将保留记录的引用组织为满足 BGZF 载荷大小限制的打包计划。
BAM 写流水线消费这些计划，并将生成的压缩块追加到各 rank 的本地输出正文。
记录在每个 rank 内保持其输入顺序，最终文件按输入区间顺序放置各 rank 本地正文，而不按坐标或 QNAME 排序。
格式转换将输入格式的读流水线连接到输出格式的写流水线。
对于 BAM 到 SAM 转换，MPE 侧转换算子将解析后的 BAM 记录引用传给 SAM 写流水线。
对于 SAM 到 BAM 转换，MPE 后处理从解析后的 SAM 记录构建打包计划，并将其提交给 BAM 写流水线。
中间记录保持有效，直到下游流水线完成对它们的消费，使两条流水线能够按批次运行，而无需额外的记录级分派层。

这些流式操作在输入划分后只需要少量 rank 间通信，因为记录处理仍在各 rank 本地进行。
相比之下，下面描述的分布式算法需要记录重分布或跨 rank 状态。

#### 2.3.2 分布式 BAM 处理

SWBAM 实现需要全局记录重组或跨记录状态的分布式 BAM 操作。
排序建立全局坐标顺序，而归组按 QNAME 对记录分组。
Fixmate 为完整的 QNAME 组更新配对信息，重复标记则跨批次和 MPI rank 边界比较候选。
这些应用复用公共 BAM 读写流水线，而应用特定算法管理记录重分布、边界处理和跨 rank 状态。

（b）基于坐标和 QNAME 的划分。

排序通过采样、重分布和归并建立全局坐标顺序（图 2）。
CPE 提取坐标键和原始 BAM 记录，而 MPE 对本地元数据排序，并从有序记录中选取样本。
根 rank 收集样本、确定全局分割点，并广播这些分割点，以定义各 MPI rank 的坐标区间。
随后，根据这些分割点交换记录。
由于接收的数据段分别有序，每个 rank 执行 $k$ 路归并，而不是再次对所有接收记录排序。
归并后的原始记录被打包为 BGZF 载荷，并通过公共 BAM 写流水线压缩。
归组使用基于 QNAME 的划分，而不是构建全局坐标顺序。
CPE 提取 QNAME 哈希、记录元数据和原始 BAM 记录。
每个哈希被分配到一个桶，每个桶映射到一个归属 rank，使相同 QNAME 的记录到达同一个 rank。
图 2（b）展示映射到六个 rank 的六个坐标区间和 66 个 QNAME 桶。
本地排序后，每个 rank 保留归属于自身的记录，并以有界数据块交换其余记录。
接收 rank 按桶、哈希和完整 QNAME 归并数据段，将同一 QNAME 的记录分组在一起，而不施加全局 QNAME 字典序。
在每组内，记录按 READ1/READ2 标志位排序，然后按原始输入顺序排序。
与 SAMtools 的标准临时分桶流程不同，SWBAM 同时支持内存归组和外存归组。[^danecek2021samtools]
排序也支持内存和外存执行。
在外存模式下，SWBAM 在配置的内存限制下生成有序段，并执行有界数据交换和流式多路归并。
归并扇入 $F$ 指定每一遍归并的有序段数上限。
如果段数超过这一上限，则在最终归并和压缩之前执行多遍中间归并（图 2（c））。

Fixmate 为相同 QNAME 的记录更新配对信息。
由于输入 BAM 已按名称归组，相同 QNAME 的记录连续出现。
MPE 扫描每个批次，并将相邻且 QNAME 匹配的记录分为一组。
如果一个组延伸到当前批次之外，则将其保留，并在处理下一个批次时继续处理。
MPI rank 边界也会出现类似情况：一个 rank 的最后一组可能延续为另一个 rank 的第一组。
因此，每个 rank 暂时保留其边界组，并与其他 rank 交换这些组的 QNAME，以识别属于同一组的片段。
随后，这些片段被传输到指定的归属 rank，以补全该组。
一旦具有相同 QNAME 的所有记录都已收集齐全，第一个 CPE 内核便确定每条记录中与配对端相关的字段和标签更新，并计算其更新后的长度。
由于标签更新可能改变记录长度，MPE 使用这些长度在输出缓冲区中分配互不重叠的区域。
随后，第二个 CPE 内核应用这些更新，并将更新后的记录写入分配给它们的区域。
支持的更新包括配对坐标、标志、模板长度，以及 `MQ`、`MC` 和 `ms` 标签。
随后，重写后的记录通过公共 BAM 写流水线序列化和压缩。
边界和内部输出段按 QNAME 组顺序组合。

**图 3：分布式重复标记**

[查看正式 PDF 图](figs/swbam_markdup_single_column_v1.pdf)

（a）边界探测与跨 rank 判定。
（b）滑动窗口中的候选替换与最终确定。

重复标记被实现为带有规模有界的边界预处理的坐标有序流式算法，同时保持原始输入顺序。
按坐标排序的 BAM 文件被划分为连续的 BGZF 块区间，每个区间分配给一个 MPI rank。
对于每个批次，共享的 BAM 读流水线解压并解析输入块，CPE 内核提取每个候选的去重键和基于质量的得分。
单端键标识参考序列、未剪切的 5′ 坐标和链方向，而双端键包括两个参考序列坐标、由方向确定的未剪切端点以及配对方向。
前一阶段的 fixmate 操作生成的 MC 和 ms 标签提供双端处理所需的配对端 CIGAR 和得分，从而避免获取配对端记录。

由于去重键坐标可能不同于用于输入划分的比对起点坐标，具有相同键的候选可能来自不同的源 rank。
MPE 将每个候选路由到由其本地端（this）的参考序列和坐标确定的归属 rank。
对于双端候选，两个端点均保留在去重键中，而本地端坐标决定其归属。
这种确定性映射保证具有相同去重键的候选被分配给同一个归属 rank。
当归属 rank 是源 rank 时，候选在本地处理；否则，仅交换其元数据。
每个归属 rank 分别维护双端和单端读段的候选状态，包括用于处理这两种类型之间相互作用的配对存在信息。
具有相同去重键的候选按基于质量的得分进行比较，并使用 QNAME 打破平局。
随后，判定在本地应用，或通过 MPI 返回源 rank，而原始 BAM 记录保留在其源 rank 上。
为减少主扫描期间的跨 rank 协调，SWBAM 对分区边界执行规模有界的预处理。
每个 rank 在其输入区间的两端各探测最多 32 个 BGZF 块，重叠的块只处理一次。
这一限制使预处理工作量有界，但不保证完整覆盖。
对于坐标为 $b$ 的边界，预处理选择同一参考序列上比对起点位于 $[b-L,b+L]$ 内的候选，并在各自的归属 rank 上进行比较。
得到的边界计划将判定与其源记录标识关联。
当探测覆盖所有所需候选区域时，可以最终确定 KEEP 和 DUP 判定。
否则，仅最终确定由已观察到的竞争候选所建立的 DUP 判定，而潜在胜出候选保持未决，留待主扫描处理。
这种保守处理防止在考虑全部相关候选之前过早确定 KEEP 判定。

在主扫描期间，每个归属 rank 维护未解决候选键的滑动窗口，并跨批次复用哈希表存储和 QNAME 缓冲区。
新到达的候选与当前胜出候选进行比较，优于当前胜出候选的候选将其替换，并将此前的胜出候选标记为 DUP。
对于其余比较仅限于本地 rank 的内部键，当下式成立时，可将其胜出记录最终确定为 KEEP：

$$
x+L\leq p_r,
$$

其中，$x$ 是去重键在当前参考序列上的当前端坐标，$p_r$ 是 rank $r$ 已处理的最新比对起点坐标。
在配置的上界 $L$ 下，这一条件保证后续处理的比对不会对应相同的去重键。
这一上界通过命令行选项 -l 指定，遵循 SAMtools 的最大预期读长约定。
我们在所有实验中使用 SAMtools 的默认值 300 bp（$L=300$ bp）。
在 SWBAM 中，$L$ 还决定候选保留范围和边界跟踪范围，但不影响去重键的构造或相等性。
与 SAMtools 一样，有界窗口机制依赖于适当的预期读长设置。
仍可能需要跨 rank 比较的候选保留在持久边界表中，直到所有可能贡献候选的 rank 均已处理超过相应释放阈值的坐标、推进到后续参考序列或到达 EOF。
需要边界跟踪时，各 rank 通过集合通信交换处理进度和 EOF 状态。
耗尽输入的 rank 继续以空批次参与，当前轮次的候选会在释放边界状态之前处理。

原始解码块保留在其源 rank 上，避免重分布完整 BAM 记录和额外的全文件解码扫描。
记录最初被赋予暂定 KEEP 状态，而未解决的候选以及等待远程判定的记录被标记为待定。
只有在块中所有记录的判定都已解决后，才压缩该块。
由于压缩可能乱序完成，SWBAM 按输入块索引和片段位置跟踪每个压缩片段，然后按原始输入顺序组装这些片段。
解码缓冲区保留到相应压缩任务完成，未解决的块在缓冲压力下临时暂存。
为使候选管理与 CPE 压缩重叠，SWBAM 在解码下一个输入批次之后启动已准备的压缩批次。
共享的 BAM 写流水线负责压缩和输出生成，而重复标记应用管理候选状态、边界信息、MPI 判定、待定块和输出顺序。
算法 1 概括这一过程。

#### 2.3.3 去重流程

SWBAM 将归组、fixmate、坐标排序和重复标记组合为端到端去重流程。
这些阶段按此顺序运行，因为 fixmate 要求将相同 QNAME 的记录分组在一起，而重复标记要求更新后的配对信息和按坐标排序的输入。
该流程首先通过归组按 QNAME 对记录分组，然后运行启用配对得分计算的 fixmate，按基因组坐标对更新后的记录排序，最后标记重复。
每个阶段使用相应的分布式 SWBAM 应用和公共 BAM 输入输出接口。
每个阶段的输出写入中间 BAM 文件，并传给下一阶段。
该流程在生成最终重复标记 BAM 文件之前，产生归组后、fixmate 更新后和坐标排序后的中间文件。
中间文件可以在使用后自动移除，也可以保留用于调试和验证。
内存限制和压缩设置被传递给相关阶段，而排序和归组在需要时可以使用其外存实现。

在我们的测量中，MPI 初始化和结束在每次调用中产生约 7 秒的开销。
随着数据集大小增加，这一开销在总运行时间中所占的比例下降。
除非另有说明，所有报告的 SWBAM 运行时间均为完整 MPI 端到端执行时间，包括 MPI 初始化和结束。
SAMtools 使用进程墙钟时间测量，包括缓冲式 NVMe 文件输入输出。
对于每个数据集和操作，SAMtools 使用已测试设置中性能最佳的线程数。
BAM 输出使用压缩级别 1。
对于归组，SWBAM 使用 66 个逻辑 QNAME 哈希桶，而 SAMtools 使用 66 个临时桶文件（`-n 66`）。
对于每个数据集和操作，我们通过扫描 SAMtools 工作线程数、联合调整 RabbitBAM 的解压和压缩线程数，并评估其 CPU 和内存放置，选取重复运行中运行时间中位数最低的配置。
报告的跨平台加速比反映了各自的硬件和存储配置，而不是仅由软件造成的性能差异。
我们在 D1–D3 上以 SAMtools 为对照，验证了所有 SWBAM 库和应用实验。
记录数和操作特定统计量均与 SAMtools 一致。
对于产生文件的操作，在排除 `@PG` 文件头条目并考虑操作特定的顺序差异后，记录内容和辅助标签均一致。

### 3.2 SWBAM 库性能

我们使用两个基准测试评估 SWBAM 的 BAM 输入输出库的扩展性：只读记录计数和无过滤读写。
只读基准测试解压 BGZF 块，将 BAM 记录解析为可复用的 `bam1_t` 对象，并对其计数。
读写基准测试还对所有记录进行打包、序列化和压缩，然后写出完整的 BAM 文件。
图 4 同时报告了包括 MPI 初始化和结束的端到端区间，以及排除这两个阶段的处理区间的吞吐量。
SWBAM 从一个扩展到十二个活跃核组时，表现出近线性的处理阶段扩展性，只读处理的加速比为 10.77–10.90 倍，读写处理为 11.54–11.58 倍，分别对应约 90% 和 96% 的并行效率。
这种扩展性通过将连续的 BGZF 输入区间分配给各 MPI rank，并利用各核组内的块级并行性实现，同时双缓冲使 MPE 侧数据移动与 CPE 执行重叠。
尽管读写处理引入了额外的打包、序列化、压缩和输出组装，这些操作仍主要在 rank 本地进行。
特别地，最终输出组装交换的是输出大小，而不是记录载荷，从而避免 rank 间记录重分布。
然而，MPI 初始化和结束在每次调用中引入约 7 秒的开销，显著降低较短工作负载的端到端扩展性。
因此，从一个到十二个核组的加速比在只读处理中降至 2.55–4.43 倍，在读写处理中降至 5.13–7.99 倍，分别对应约 21%–37% 和 43%–67% 的端到端并行效率。
这一开销在短时只读执行中尤为明显：例如，在十二个核组下，D1 的处理仅需 1.38 秒，而完整 MPI 区间为 8.53 秒。
较长的读写工作负载能够更有效地摊薄固定 MPI 开销，凸显了 BAM 处理扩展性与 MPI 启动和关闭额外成本之间的区别。

我们进一步在六个活跃核组下，将 SWBAM 与 SAMtools 和 RabbitBAM 比较（表 3）。
基于处理时间，SWBAM 相对于 SAMtools 在只读和读写处理中分别实现了 3.82–4.35 倍和 2.77–3.41 倍加速，相对于 RabbitBAM 则分别实现了 2.44–3.34 倍和 1.72–3.26 倍加速。
这些收益来自将记录处理分布到各 MPI rank 和 CPE。
与在主线程上保留记录遍历的 SAMtools 不同，SWBAM 在 CPE 上执行解压和记录解析。
与 RabbitBAM 相比，SWBAM 在读取时避免中间记录块组装，在写入时将序列化和压缩集成到同一个 CPE 内核中，从而减少中间数据处理和调度开销。
计入 MPI 初始化和结束后，相对于 SAMtools 的加速比分别降至 1.12–1.93 倍和 1.77–2.19 倍，相对于 RabbitBAM 的加速比则分别为 0.64–1.24 倍和 1.16–1.82 倍。
RabbitBAM 在 D1 和 D3 的只读处理中仍然更快，而 SWBAM 在全部三个数据集的读写处理中保持优势，凸显了 MPI 启动和关闭对较短工作负载的影响。

### 3.3 SWBAM 应用性能

我们在流式和分布式 BAM 操作以及四阶段去重流程上评估 SWBAM 应用。
所有 SWBAM 应用测试均使用单个神威节点上的全部六个核组，而 SAMtools 针对每个数据集和操作使用实测最优线程数。
BAM 输出使用压缩级别 1。
除非另有说明，表格按照概述中的计时定义，比较 SWBAM 的完整端到端运行时间（包括 MPI 初始化和结束）与 SAMtools 的进程墙钟时间。

#### 3.3.1 流式 BAM 处理

尽管 MPI 初始化和结束额外引入约 7 秒开销，SWBAM 在四项流式操作中仍实现了 1.03–4.61 倍的加速比（表 4），其中 BAM 到 SAM 转换的收益最大。
测得的加速比既反映各项操作的并行性，也反映 MPI 启动和关闭的开销，尤其是对于较短的工作负载。
标志统计实现了 1.03–1.82 倍的加速比，受益于 CPE 上并行执行的 BGZF 解码、记录解析和标志累计，而 SAMtools 在其主线程上保留记录遍历和计数器更新。
MAPQ 过滤实现了 1.57–2.22 倍加速比，因为与标志统计不同，它要求对保留记录进行序列化和 BGZF 压缩。
由于 81.28%–95.82% 的输入记录通过过滤阈值，仍保留了大量输出处理工作。
尽管两种实现都并行执行 BGZF 压缩，SWBAM 还额外进行记录打包和最终输出组装。
BAM 到 SAM 实现了最高的加速比，范围为 3.17–4.61 倍。
这一优势来自将完整的记录处理路径分布到六个 rank，其中 CPE 通过批次级记录指针交接执行记录构建和并行 SAM 格式化。
SAMtools 也并行执行 SAM 格式化，但保留主线程上的记录遍历及向有序输出分发器的提交。
因此，由此获得的优势反映了完整转换流水线在组织方式上的差异，而不仅仅是格式化并行性的差异。
SAM 到 BAM 在 D1、D2 和 D3 上分别实现了 1.96 倍、2.95 倍和 2.26 倍的加速比。
两种实现都并行执行 SAM 解析和 BGZF 压缩。
SWBAM 将解析和压缩分布到各 rank 本地的 CPE 流水线，而 SAMtools 使用共享工作线程池，但保留主线程上的记录提交和 BAM 序列化。

#### 3.3.2 分布式 BAM 处理

尽管 MPI 初始化和结束额外引入约 7 秒开销，SWBAM 在四项分布式操作中仍实现了 1.33–3.32 倍的加速比。
坐标排序最稳定地获益，而重复标记表现出最强的数据集依赖。
这些差异反映了每项操作所能提供的并行程度，以及跨批次和 rank 维护操作特定状态的成本。

坐标排序实现了 2.85–3.32 倍的加速比。
尽管 SAMtools 并行执行基数排序和 BGZF 输入输出，其主线程仍将记录装入共享内存区，并推进最终的堆归并。
SWBAM 将记录提取、本地排序、坐标划分和区间本地归并分布到六个 rank，而 CPE 处理 BGZF 块。
它还在保留原始 BAM 载荷的同时，对紧凑的坐标元数据排序，从而避免为每条存储记录构造独立的 `bam1_t` 对象。
因此，其优势来自将更多端到端重排流水线工作分布执行并减少记录表示开销，而不是来自更快的本地排序算法。
归组实现了 2.42–2.67 倍加速比。
SAMtools 将记录写入压缩的临时桶，随后在主线程上读取这些桶并对其排序。
SWBAM 将哈希桶分布到各 rank，而 QNAME 比较和载荷打包仍是 MPE 侧操作。
对于 D1 和 D3 上的归组，SWBAM 使用其内存归组实现，避免了 SAMtools 所需的临时文件写入和后续读取。
在 D2 上，尽管外部有序段处理增加了中间写入和归并，归组和坐标排序仍分别实现了 2.67 倍和 3.32 倍的加速比。
Fixmate 实现了相对稳定的 1.67–1.93 倍加速比。
SAMtools 在主线程上执行 QNAME 分组和配对字段更新，工作线程主要处理 BGZF 输入输出。
SWBAM 将配对更新规划和记录重写下放到 CPE，但 QNAME 组扫描和输出偏移构建仍在每个 MPE 上进行。
这些剩余的 MPE 侧操作连同输出序列化和压缩，限制了下放配对更新所带来的收益。
重复标记在 D1、D2 和 D3 上分别实现了 2.61 倍、2.19 倍和 1.33 倍加速。
尽管 CPE 加速了 BGZF 解码、候选提取和压缩，候选状态维护和跨 rank 协调仍主要是 MPE 侧任务。
由此产生的候选状态维护开销取决于未解决候选的数量，以及必须维护其状态的时间。
在 D1 和 D2 上，边界预处理覆盖了所需区域，避免了主扫描期间的候选载荷交换。
然而，D2 上更大的未解决状态规模和更严重的 rank 本地工作负载不均衡增加了状态管理成本，并延缓了集体推进。
D3 因边界部分覆盖而需要继续维护边界状态和协调跨 rank 候选，从而产生额外开销。
这些因素连同未解决块和有序输出生成所需的缓冲，共同解释了性能对数据集的依赖。
总体而言，重复标记效率不仅取决于输入大小，还取决于候选状态管理、边界协调和 rank 本地工作负载均衡。

SWBAM 在 D1 上用 221.49 秒完成四阶段去重流程，在采用外部有序段处理的 D2 上用 551.76 秒，在 D3 上用 257.62 秒，分别实现了 2.70 倍、2.39 倍和 2.27 倍加速（表 6）。

## 4 结论（Conclusions）

本工作提出 SWBAM，这是一个用于在神威异构众核体系结构上快速且可扩展地处理 BAM/SAM 文件的库和应用套件。
SWBAM 将可复用的基于批次的 MPE-CPE 流水线与优化的 CPE 内核结合，以支持高效的 BAM/SAM 输入输出和记录处理，并提供一系列 rank 本地和分布式操作，将它们集成为完整的四阶段去重流程。
实验结果表明，将库从一个核组扩展到十二个核组时，处理阶段并行效率达到 90%–96%。
尽管 MPI 初始化和结束在每次调用中引入约 7 秒开销，SWBAM 在包括 MPI 开销的情况下，相对于 SAMtools 在流式操作上实现了 1.03–4.61 倍加速，在分布式操作上实现了 1.33–3.32 倍加速，在完整去重流程上实现了 2.27–2.70 倍加速。
这些结果表明了异构众核执行在加速多种 BAM/SAM 操作方面的有效性。
未来工作将重点改善不规则坐标分布下的重复标记性能，并降低短时运行工作负载的 MPI 开销。
