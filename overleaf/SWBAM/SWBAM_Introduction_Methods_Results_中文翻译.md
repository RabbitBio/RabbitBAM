## 1 引言（Introduction）

测序数据的快速增长持续增加了基因组数据分析的计算和存储需求。[^amarasinghe2020opportunities][^goodwin2016coming][^schmidt2017ngs]
序列比对后，结果通常以 SAM（Sequence Alignment/Map）或 BAM（Binary Alignment/Map）格式存储。[^li2009samtools]
随后，这些文件在用于变异检测等下游分析之前，会经过一系列操作，包括统计、过滤、格式转换、排序、配对信息更新和重复标记。
因此，许多分析流程会多次读取、重组和重写大型 BAM 文件。
随着测序数据集持续增长，高效的 BAM 和 SAM 处理对于大规模基因组分析的整体吞吐量变得越来越重要。

SAMtools 和 HTSlib 为 BAM 和 SAM 处理提供了广泛使用的软件基础设施，并支持格式转换、排序、索引和重复标记等操作。[^danecek2021samtools][^bonfield2021htslib]
一些工具进一步提高了特定 BAM 操作的性能。
Sambamba 对常见的比对文件操作采用多线程处理，[^tarasov2015sambamba] 而 quickBAM 为已排序且已建立索引的 BAM 文件提供并行访问。[^pitman2023quickbam]
我们此前的工作 RabbitBAM 专注于多核 CPU 平台上的通用 BAM 输入输出，并通过预解析、并行解析、内存池和无锁队列提高并行效率。[^yan2025rabbitbam]
这些方法表明，BAM 处理能够从面向体系结构的优化中显著受益。
然而，它们的并行模型主要围绕传统 CPU 线程设计，并未直接应对异构众核执行和分布式 BAM 处理。

新一代神威体系结构提供了强大的计算能力，但也引入了不同的执行模型。
SW26010-Pro 处理器由多个核组（Core Group，CG）组成，每个核组包含一个管理处理单元（Management Processing Element，MPE）和 64 个计算处理单元（Compute Processing Element，CPE），而 MPI 通常用于不同核组上的进程间通信。[^zhu2021sunway]
SWQC 和 SWBWA 等已有工作表明，通过将计算密集型操作移至 CPE，并针对 MPE-CPE 执行重新设计原有并行流程，生物信息学应用可以在这一体系结构上获得高性能。[^yan2025swqc][^yan2026swbwa]
然而，BAM 处理带来了额外挑战，因为它结合了压缩文件输入输出、记录解析、格式转换和应用特定的数据依赖。

神威上的高效 BAM 处理面临三个主要挑战。
首先，BAM 和 SAM 库天然提供面向记录的操作，而为单条记录启动和同步 CPE 任务会引入过多的细粒度开销。
因此，高效的设计既需要更粗粒度的执行单元，也需要在 MPE 与 CPE 之间进行合适的工作划分。
处理流程必须协调 MPE 侧的数据准备和后处理与 CPE 计算，以减少同步开销和空闲时间。
其次，分布式 BAM 处理需要可扩展的数据访问和输出组织。
多个 MPI rank 应直接处理分配给自己的输入区域，并生成有效的全局输出，而不依赖单个 rank 分发或收集完整文件。
第三，BAM 应用具有差异很大的数据依赖。
统计和过滤等简单操作可以在单个批次上独立执行，而排序需要全局数据重分布，fixmate 需要基于 QNAME 的分组，重复标记则需要按坐标有序的跨记录和跨 rank 状态。

为应对这些挑战，我们开发了 SWBAM，这是一个面向神威众核平台的高性能 BAM 和 SAM 处理库及应用框架。
在库层面，SWBAM 提供四条基于批次的 MPE-CPE 流水线，用于 BAM 读取、BAM 写入、SAM 读取和 SAM 写入。
该库将存储访问与计算分离，并支持可复用的输入输出、批次管理、CPE 调度和输出组件。
可以根据所需操作，将不同的处理算子接入这些流水线。
SWBAM 还优化了用于 BGZF 压缩和解压、BAM 解析、SAM 解析和格式化以及记录序列化的主要 CPE 内核。
在应用层面，这些公共组件被复用于实现流式操作和分布式 BAM 算法，包括统计、过滤、BAM/SAM 转换、排序、归组、fixmate 和重复标记。
分布式应用进一步管理全局数据重分布、跨 rank 通信和算法特定状态。

SWBAM 的一项关键设计原则是在批次边界提供灵活性，同时保持高效的记录级处理。
流水线和算子的选择在批次级进行，而性能关键的记录操作则在 CPE 内核中静态组合。
例如，BGZF 解压、BAM 解析以及记录级统计或过滤可以在一次 CPE 启动中完成。
这避免了逐记录的运行时分派和不必要的中间处理。
随后，可以通过 MPE 侧的批次后处理连接不同流水线，构建 BAM 到 BAM、BAM 到 SAM 和 SAM 到 BAM 转换等完整操作。
通过这种方式，SWBAM 在保留优化后的 CPE 执行路径的同时，提高了代码复用程度。

基于该库，我们进一步为更复杂的 BAM 操作开发分布式实现。
排序和归组分别依据坐标或 QNAME 信息在 MPI rank 之间重分布记录。
Fixmate 处理可能跨越批次和 rank 边界的 QNAME 组。
重复标记采用单遍坐标流式设计，通过滑动窗口、跨 rank 边界处理和增量输出来控制内存使用。
这些应用进一步组合成端到端去重流程，由归组、fixmate、坐标排序和重复标记组成。

本文的主要贡献如下：

- 我们设计了 SWBAM，这是一个面向异构神威众核体系结构的可复用 BAM/SAM 处理库。SWBAM 提供四条基于批次的 MPE-CPE 流水线，以及公共输入输出、双缓冲、分布式数据访问和输出支持。
- 我们开发了可复用且经过优化的 CPE 处理组件，用于 BGZF 压缩和解压、BAM/SAM 解析和格式化以及记录级操作。SWBAM 在批次边界组合流水线，并在 CPE 内核中静态融合记录处理，从而减少细粒度调度和中间处理开销。
- 我们在 SWBAM 之上实现了分布式 BAM 应用，包括排序、归组、fixmate 和重复标记。这些应用复用公共库，同时引入应用特定的数据重分布、跨 rank 状态管理和单遍坐标流式重复标记算法。
- 我们将这些应用集成为完整的分布式去重流程，并在神威平台上从库和应用两个层面评估 SWBAM。

### 2.2 SWBAM 库设计

#### 2.2.1 BAM/SAM 输入输出

SWBAM 提供可复用的 BAM/SAM 输入输出组件，使应用无需单独实现数据访问。
应用可以使用相同的处理流水线和不同的输入输出方式。
对于 BAM 输入，SWBAM 将 BGZF 块划分为连续区间，并将每个区间分配给一个 MPI rank。
根 rank 扫描数据区域，并构建包含块偏移和压缩大小的有序索引。
它将压缩数据读入一个 8 MiB 缓冲区，并在内存中检查连续的 BGZF 头，从而减少块边界检测期间的小规模文件读取。
随后，根 rank 将索引广播给所有 rank。
这些块被划分为块数近似相等的连续区间。
在处理期间，每个 rank 仅通过 POSIX 或 MPI-IO 读取分配给自己的块。
在每个连续批次内，BGZF 块被直接读入用于 CPE 处理的独立目标缓冲区。
POSIX 路径使用 `preadv` 将一个连续文件区域读入缓冲区列表。
MPI-IO 路径使用派生数据类型，将每个块放入其对应的目标缓冲区。
这两条路径都避免了中间缓冲区及随后对各个块的复制。
对于 SAM 输入，SWBAM 将文件头之后的文本划分为近似相等的字节区间。
它将分区边界调整到行尾，使每条记录在单个 rank 内保持完整。
每个 rank 通过 POSIX 或 MPI-IO 读取分配给自己的区间。

SWBAM 分两个阶段写出分布式输出，因为每个 rank 产生的数据量不同。
每个 rank 首先将其输出正文追加到位于内存或临时文件中的本地存储。
在自动模式下，当一次追加将超过内存限制时，该存储切换到临时文件。
处理完成后，各 rank 交换正文大小，并使用前缀和按 rank 顺序计算文件偏移。
每个偏移由文件头大小和在其之前的所有 rank 的输出大小确定。
在 MPI-IO 模式下，每个 rank 通过固定大小的缓冲区读取其暂存正文，并将其写入分配的文件区域。
这避免了在根 rank 上收集完整的输出正文，并限制了最终写出期间的内存使用。
BAM 输出由一个文件头、按 rank 顺序排列的各 rank 本地压缩正文，以及一个 BGZF EOF 块组成。
SAM 输出由一个文本文件头及其后的各 rank 本地文本正文组成。
基于文件的暂存使 SWBAM 能够处理大于可用暂存内存的输出，而无需将整个输出保留在内存中。

#### 2.2.2 基于批次的 MPE-CPE 流水线

SWBAM 提供四条基于批次的 MPE-CPE 流水线，用于 BAM 读取、BAM 写入、SAM 读取和 SAM 写入。
基于批次的执行减少了逐记录处理所涉及的内核启动和同步开销。
MPE 准备输入批次并管理任务执行，而 CPE 执行相应的处理内核。

BAM 读流水线处理压缩 BGZF 块批次。
CPE 解压这些块，并在需要时解析 BAM 记录或执行应用特定操作。
BAM 写流水线接收未压缩数据块或 BAM 记录批次。
CPE 直接压缩输入块，或在压缩前序列化记录。
这两条流水线产生或消费 BGZF 块批次，并支持 rank 本地数据处理。
SAM 读流水线将 rank 本地 SAM 文本转换为 `bam1_t` 记录批次。
MPE 将文本划分为与记录边界对齐的文本块。
CPE 首先复制文本并统计记录数，然后在独立内核中解析 SAM 字段。
SAM 写流水线将 `bam1_t` 记录批次转换为 SAM 文本。
CPE 将记录格式化到独立文本缓冲区中，MPE 按记录顺序追加结果。

SWBAM 使用交替缓冲区，使 MPE 侧工作与 CPE 执行重叠，如图 1 中的 BAM 读取调度所示。
对于 BAM 读取，当 CPE 处理当前批次时，MPE 读取下一个压缩批次。
对于 BAM 写入，当 CPE 压缩当前批次时，MPE 写出前一个压缩批次。
SAM 处理根据流水线阶段和数据依赖采用类似的重叠。
这些策略减少空闲时间，并跨批次复用已分配的缓冲区，而无需在同一个核组内并发执行多个 CPE 内核。

#### 2.2.3 流水线组合与算子

SWBAM 将批次调度、任务适配和记录级处理分离。
BAM 流水线运行时系统管理公共批次缓冲区、启动并等待 CPE 内核完成，以及调用 MPE 侧钩子。
MPE 侧批次算子提供内核入口和任务特定参数、绑定数据缓冲区、验证结果，并实现所需的批次后处理。
CPE 内核执行选定的计算，而记录级操作定义应用于每条已解析记录的任务。

记录级组合将具体的处理动作绑定到公共 BAM 记录遍历过程，而不是为每条记录调用批次算子。
C++ 模板在编译每个内核时确定 action 类型。
MPE 在运行时从预先构建的内核中选择，包括过滤和直通变体，并传入过滤参数等运行时选项。
记录遍历直接调用该动作，而不进行逐记录的虚函数或函数指针分派。

批次级组合在内核完成并通过验证后，通过 MPE 后处理连接流水线结果。
记录计数仅使用 BAM 读流水线：CPE 将记录解析到可复用的 `bam1_t` 对象中，MPE 对各块的计数求和。
BAM 到 BAM 处理连接 BAM 读写流水线。
MPE 将保留的记录组织为 BGZF 打包计划，并将其提交给 BAM 写出器进行序列化和压缩。
这些计划引用现有记录；规划过程可能复制指针列表，但不会复制记录载荷或转移所有权。
BAM 到 SAM 和 SAM 到 BAM 处理以类似方式连接相应的读写流水线。

缓冲区生命周期由拥有该存储的组件决定。
对流水线所拥有数据的引用仅在相应缓冲区被复用或释放之前有效。
在 BAM 到 BAM 处理中，已解析记录位于读算子的存储中，并保持有效，直到下游写调用完成对这些记录的消费。
该调用在返回前完成序列化和压缩，但压缩输出仍可能保留在缓冲区中，等待后续写出。
跨批次保留数据的应用通过其算子或算法特定存储管理这些数据的生命周期。
它们可以复制所需数据，或将内核输出直接写入生命周期更长的存储。

#### 2.2.4 CPE 内核优化

SWBAM 进一步优化在 CPE 上执行的主要 BAM 和 SAM 处理内核，以减少计算、内存分配和中间数据移动。
BGZF 压缩和解压在连续 BAM 处理期间被反复调用，而重复创建相应的编解码器对象会引入不必要的开销。
因此，SWBAM 为各个 CPE 维护可复用的 libdeflate 压缩器和解压器对象。
解压器在首次使用时创建，随后由同一个 CPE 在后续批次中复用。
压缩器同样按压缩级别缓存，并仅在所需级别改变时重新创建。
对于面向性能的级别 1 压缩路径，SWBAM 进一步调整匹配搜索策略，以在保留有效 BGZF 输出的同时减少压缩工作量。

BAM 解析也直接在 CPE 上执行，并与记录级处理集成。
BGZF 块解压后，SWBAM 使用公共解析器遍历解码块中的 BAM 记录。
常用记录操作，包括计数、标志统计、基础统计、过滤和直通处理，复用相同的遍历框架。
所选操作在构建 CPE 内核时确定，并在记录遍历期间直接执行。
因此，BGZF 解压、BAM 解析和所需的记录操作可以在一次 CPE 启动中完成，而无需逐记录的运行时分派。
SWBAM 还跨记录和批次复用预分配的记录缓冲区和临时工作空间，减少解析期间的重复内存分配。

SWBAM 对 BAM 输出采用类似的融合策略。
当输入已组织为未压缩 BGZF 块时，CPE 直接压缩这些块。
当输入由 BAM 记录组成时，SWBAM 首先将记录序列化为可供 BGZF 处理的块，然后在同一次 CPE 执行中进行压缩。
这避免了在序列化和压缩之间，在 MPE 上构建另一份完整的 BAM 表示。
输出缓冲区和临时工作空间跨批次复用，进一步减少内存管理开销。

SAM 流水线的主要处理阶段也使用 CPE 内核实现。
SAM 读取首先将文本划分为与记录边界对齐的块，并使用 CPE 内核进行文本复制与计数、记录解析。
SAM 写入在 CPE 上将 BAM 记录批次格式化为 SAM 文本。
结合上述基于批次的执行模型，这些内核级优化将主要的解析、格式化、压缩和解压工作移至 CPE，同时减少 MPE 上的重复分配和中间处理。

### 2.3 基于 SWBAM 库构建的应用

#### 2.3.1 流式 BAM 处理

SWBAM 实现了多种流式 BAM 和 SAM 操作，它们单遍处理输入，而不进行全局记录重排。
这些操作包括标志统计、基础统计、BAM 过滤和重写，以及 BAM 和 SAM 之间的格式转换。
由于一个批次的处理不依赖远处的记录，每个 MPI rank 可以使用公共 SWBAM 流水线，独立处理分配给自己的输入区间。
只有统计结果或输出布局信息等较小的最终结果需要在 MPI rank 之间交换。

对于统计操作，SWBAM 使用带有应用特定 CPE 算子的 BAM 读流水线。
flagstat 和基础统计算子在 CPE 内核中结合 BGZF 解压、BAM 解析和记录级统计。
每个批次产生 rank 本地计数，CPE 处理后在 MPE 上累加这些计数。
处理完全部本地批次后，通过 MPI 归约合并各 rank 的本地结果，以生成最终统计。
这种设计避免了生成额外的 BAM 数据流，并将主要记录处理保留在 CPE 上。

BAM 过滤和重写通过连接 BAM 读流水线与 BAM 写流水线实现。
读侧变换算子执行解压、解析和可选的记录过滤。
随后，在 MPE 上将保留记录组织为记录打包计划，并提交给 BAM 写流水线，由 CPE 执行记录序列化和 BGZF 压缩。
对于被过滤器移除的记录，不生成输出记录。
在不需要过滤时，同一条流水线也可以在直通模式下运行。
每个 MPI rank 生成自己的有序输出正文，随后将其放入最终 BAM 文件中的对应位置。

格式转换通过组合相应的读写流水线实现。
对于 BAM 到 SAM 转换，BAM 读流水线使用直通算子解压并解析输入记录，再将解析后的记录按批次传给 SAM 写流水线，在 CPE 上并行格式化。
对于 SAM 到 BAM 转换，SAM 读流水线首先识别完整的 SAM 记录，并将其解析为 BAM 记录，之后 BAM 写流水线将记录序列化并压缩为 BGZF 块。
中间记录仅为当前批次保留，并在下游流水线完成处理后释放或复用。
这种批次级组合保留记录顺序，同时避免了两条流水线之间额外的记录级分派层。

与下文描述的分布式算法相比，这些流式操作只需要少量跨 rank 通信。
大部分计算和数据移动都在各 rank 本地进行，而 MPI 主要用于最终统计汇总和分布式输出组织。
因此，它们直接受益于基于批次的 MPE-CPE 流水线，并为评估 SWBAM 的基础处理效率提供了代表性应用。

#### 2.3.2 分布式 BAM 处理

SWBAM 进一步实现了需要全局数据重组或跨记录状态的分布式 BAM 操作。
与流式操作不同，这些应用无法让每个 MPI rank 完全独立地处理，因为属于同一全局顺序、QNAME 组或重复组的记录可能分布在不同 rank 上。
因此，SWBAM 复用公共 BAM 读写流水线进行本地数据处理，而应用层管理算法特定元数据、MPI 通信和全局状态。
这种设计使 BGZF 输入输出和 CPE 处理保持可复用，同时允许每个应用采用适合其数据依赖的分布式算法。

##### 排序与归组

**图 2：分布式排序与归组**

[查看正式 PDF 图](figs/swbam_distributed_reordering.pdf)

（a）记录重分布与归并。
（b）基于坐标和 QNAME 的划分。
（c）内存处理与外部有序段处理。

排序和归组共享图 2 中的分布式流程，但使用不同的划分键。
对于坐标排序，SWBAM 首先使用 CPE 从每条记录中提取坐标键和原始 BAM 数据。
每个 rank 对其本地元数据排序，并从有序记录中选取样本。
收集这些样本以确定全局分割点，由这些分割点在 MPI rank 之间划分坐标空间。
随后，根据这些分割点划分本地记录，并将其交换到目标 rank。
由于每个源 rank 发出的记录已经有序，接收 rank 对收到的数据段执行 k 路归并，而不是再次对所有接收记录排序。
最终的原始记录被直接打包为 BGZF 载荷，并通过公共 BAM 写流水线压缩。
当数据超过配置的内存限制时，SWBAM 生成有序段（runs），并执行有界数据交换和流式多路归并，使同一分布式排序方案能够在外存模式下运行。

归组采用类似的分布式组织方式，但按 QNAME 而不是基因组坐标对记录分组。
在 BAM 读取期间，CPE 提取 QNAME 哈希、QNAME 相关元数据和原始记录数据。
记录被分配到桶中，每个桶映射到一个归属 rank，使相同 QNAME 的记录由同一个 rank 处理。
本地排序后，归属于本 rank 的记录保留在本地，而归属于其他 rank 的记录以有界数据块交换。
随后，按 QNAME 顺序归并收到的数据段，将同一 QNAME 的记录放在一起，并保留组内所需的顺序。
与排序类似，SWBAM 同时提供内存和外存实现。
外存模式在配置的内存限制下存储中间有序段，并在将结果传给 BAM 写流水线之前使用流式多路归并。

图 2（b）展示用于排序的六个坐标区间，以及用于归组的、映射到六个 rank 的 66 个 QNAME 桶。
在外存模式下，归并扇入 F 限制每一遍的输入段数；当超过这一限制时，会使用额外的归并遍数，如图 2（c）所示。

##### Fixmate

Fixmate 要求将相同 QNAME 的记录作为一组处理，因此引入了跨批次和 rank 边界的状态。
SWBAM 通过公共 BAM 读流水线读取已按名称归组的输入，并在 MPE 上对连续的同 QNAME 记录分组。
完整组立即处理，而批次边界处的不完整组保留到下一批次可用时。
一个 QNAME 组也可能跨越 MPI rank 边界。
SWBAM 识别这些边界组，并在更新配对信息之前，将其片段传送到选定的归属 rank。
对于每个完整组，一个 CPE 规划内核确定所需的配对字段和标签更新，以及输出大小。
随后，MPE 计算输出偏移，第二个 CPE 内核并行重写记录。
当前实现更新配对坐标、标志、模板长度，以及所支持 fixmate 模式所需的 `MQ`、`MC` 和 `ms` 标签。
重写后的记录最终通过公共 BAM 写流水线序列化和压缩。

（a）边界探测与跨 rank 判定。

重复标记针对按坐标有序的 BAM 数据实现，并且同时需要跨记录比较和跨 rank 协调。
SWBAM 首先使用 BAM 读流水线解码并解析输入批次，而应用特定的 CPE 处理仅提取重复检测所需的信息。
候选根据其坐标区间分配给归属 rank，使大多数候选留在本地 rank，仅需要交换属于其他坐标区间的候选。
每个归属 rank 为配对候选和单读段候选分别维护状态，并比较具有相同重复键的记录，以确定要保留的记录。

图 3（a）展示对未剪切 5′ 坐标相同、但比对起点不同的候选所作的跨 rank 判定。
交换候选元数据，以选择得分更高的代表记录。
图 3（b）展示内部正向单端读段的候选替换和最终确定。
键的数值标签表示坐标分量 x；当 x+L≤p 时，赋予最终 KEEP 状态，其中 L 是最大读长，p 是本地坐标进度。
未决边界候选还需要安全的跨 rank 进度。
算法 1 描述完整处理流程。

**算法 1：rank r 上的分布式重复标记**

输入：分配给 rank `r` 的按坐标排序的 BAM 块；最大读长 `L`。

输出：rank 本地已进行重复标记的 BGZF 正文。

```text
P_r <- 探测首尾块(r, 32)
G <- 全收集各 rank 的起始坐标()
covered <- 检查边界覆盖情况(P_r, G, L)          // 检查所有 rank

如果 covered 为真：
    E_r <- 选取边界候选(P_r, G, L)
    H_r <- 解决边界候选(E_r, G)                // 交换元数据和判定
否则：
    H_r <- disabled
    // 将边界候选保留在保守窗口中

初始化候选窗口 W_r、解码块缓冲区 Q_r 和有序输出存储 O_r
T <- 全归约取最大值(本地批次数)

对于 t = 1, ..., T：
    (B, C_r, p_r) <- 解码并提取批次(t)
    // 本地输入结束后，当前批次为空
    将带有暂定 KEEP 状态的解码块 B 加入 Q_r
    将预计算的边界判定 H_r 应用到 Q_r
    从 C_r 中移除已解决的边界候选

    (C_local, C_remote) <- 按坐标归属划分(C_r)
    将 C_remote 对应的源记录标记为 pending
    C_owner <- C_local ∪ 交换候选(C_remote)
    更新候选窗口(W_r, C_owner, p_r, L, Q_r, D_remote)
    // 应用本地判定并更新 pending 状态
    D_received <- 将判定路由回源 rank(D_remote)
    将 D_received 应用到 Q_r 中的 pending 记录
    压缩就绪块(Q_r, O_r)

验证跨 rank 的坐标顺序
将 W_r 中剩余候选的最终状态设为 KEEP
将剩余远端判定路由回源 rank
将收到的判定应用到 Q_r
执行 压缩就绪块(Q_r, O_r)，直到 Q_r 为空
等待压缩完成
按输入块顺序完成 O_r

过程 压缩就绪块(Q_r, O_r)：
    当 Q_r 中仍有判定完成但尚未压缩的块时：
        选择其中输入块索引最小的就绪块 P
        将最终重复判定应用到 P
        将 P 标记为处理中，并提交压缩
        压缩完成后，按输入块索引将结果存入 O_r
        释放解码数据，并从 Q_r 中移除 P
```

为限制内存使用，SWBAM 以单遍坐标流式方式执行重复标记。
候选通过滑动窗口按坐标顺序处理，无法再与未来记录交互的候选从活跃状态中移除。
靠近 MPI rank 边界的记录需要额外处理，因为与它们重复的记录可能位于相邻 rank。
因此，SWBAM 在 rank 分区周围构建边界 halo，并在作出最终判定之前交换所需的候选信息。
边界探测在 rank 分区两端各解码最多 32 个 BGZF 块，并且仅在所有探测都覆盖所需 halo 时预计算边界判定。
重复判定尚未完成的解码块暂时保留在解码块缓冲区中。
一个块的全部本地和远端判定可用后，SWBAM 更新重复标志，并将就绪块提交给公共 BAM 写流水线。
就绪块可以先于更早的未决块压缩；有序输出存储在 rank 本地输出中保留输入块顺序。
解码块存储在压缩完成后释放。
公共库管理批次调度和压缩，而应用维护滑动窗口、MPI 判定、边界状态、待处理块和块顺序索引。

#### 2.3.3 去重流程

SWBAM 通过组合归组、fixmate、坐标排序和重复标记，提供端到端去重流程。
这四个阶段依次执行，因为重复标记需要配对信息和按坐标有序的输入，而在相同 QNAME 的记录分组后，配对信息的更新最高效。
因此，该流程首先执行 collate，按 QNAME 对记录分组，然后运行启用配对得分计算的 fixmate，按基因组坐标重排更新后的记录，最后执行重复标记。

每个阶段使用上述相应的分布式 SWBAM 应用实现，并复用公共 BAM 输入、处理和输出接口。
一个阶段的输出写为中间 BAM 文件，并用作下一阶段的输入。
具体而言，该流程在生成最终重复标记 BAM 文件之前，生成归组后、fixmate 更新后和坐标排序后的中间 BAM 文件。
这些中间文件可以在不再需要后自动移除，也可以保留用于调试和验证。
内存限制和压缩设置被传递给相应阶段，而 sort 和 collate 在需要时还可以使用其外存实现。

这些结果比较的是所述存储条件下测得的平台配置，而不是相同数量的处理器核心。

当处理区间较短时，MPI 启动和关闭仍然重要。
例如，在十二个核组上读取 D1，在处理区间内耗时 1.38 秒，而在完整 MPI 区间内耗时 8.53 秒。
因此，上述扩展性结果描述的是处理吞吐量，而不是完整 MPI 调用的吞吐量。

### 3.3 SWBAM 应用性能

#### 3.3.1 流式 BAM 处理

我们评估四项流式应用，以考察公共处理流水线的有效性。
这些应用包括标志统计、比对质量过滤，以及 BAM 与 SAM 之间的转换。
SWBAM 在六个节点上使用六个活跃核组，而 SAMtools 使用针对每个应用和数据集选定的线程配置。
过滤保留 MAPQ ≥ 30 的记录，BAM 输出使用压缩级别 1。
表 4 报告概述所定义的计时和存储条件下的三次运行时间中位数及其比值。

**表 4：流式 BAM 操作的运行时间比较**

| 数据集 | 应用 | SAMtools | SWBAM | 比值 | `-@` |
| --- | --- | ---: | ---: | ---: | ---: |
| D1 | 标志统计 | 12.24 | **3.54** | 3.46 | 8 |
| D1 | MAPQ ≥ 30 | 31.27 | **9.39** | 3.33 | 96 |
| D1 | BAM-to-SAM | 77.17 | **13.92** | 5.55 | 96 |
| D1 | SAM-to-BAM | 38.01 | **12.24** | 3.10 | 24 |
| D2 | 标志统计 | 29.30 | **8.96** | 3.27 | 8 |
| D2 | MAPQ ≥ 30 | 70.59 | **24.68** | 2.86 | 96 |
| D2 | BAM-to-SAM | 182.33 | **32.44** | 5.62 | 96 |
| D2 | SAM-to-BAM | 111.65 | **30.74** | 3.63 | 96 |
| D3 | 标志统计 | 10.94 | **3.47** | 3.15 | 48 |
| D3 | MAPQ ≥ 30 | 25.28 | **9.02** | 2.80 | 96 |
| D3 | BAM-to-SAM | 58.92 | **11.48** | 5.13 | 48 |

计时和存储条件遵循概述。

标志统计和过滤在三个数据集上表现出一致的收益。
标志统计在 D1–D3 上的运行时间比值分别为 3.46 倍、3.27 倍和 3.15 倍。
SWBAM 在 CPE 读算子中结合 BGZF 解压、BAM 解析和标志计数，然后归约各 rank 的本地计数。
无需生成重写后的 BAM 输出。
过滤实现的比值为 3.33 倍、2.86 倍和 2.80 倍。
尽管 MAPQ 检查在记录遍历期间进行，保留记录仍必须打包、序列化、压缩和写出。
这条额外的输出路径解释了为什么在每个数据集内，过滤比标志统计耗时更长。

BAM 到 SAM 转换在四项应用中获得最大的运行时间比值。
这些比值在 D1–D3 上分别为 5.55 倍、5.62 倍和 5.13 倍。
SWBAM 将 BAM 读流水线连接到 SAM 写流水线，解压、记录解析和文本格式化在 CPE 上执行。
结果是未压缩的 SAM 文本，因此无需进行 BGZF 输出压缩。
然而，完整文本输出仍是所测处理区间的一部分。
因此，这些比值反映所述存储条件下的完整转换路径，而不只是文本格式化速度。

SAM 到 BAM 转换的相对收益表现出更大的变化。
其在 D1 和 D2 上的比值为 3.10 倍和 3.63 倍，而在 D3 上为 1.45 倍。
反向转换必须解析文本字段、构建变长 BAM 记录、准备块打包计划，并对输出进行序列化和压缩。
因此，它采用不同于 BAM 到 SAM 的处理路径，而不是简单地反向执行相同操作。
在 D3 上，SWBAM 耗时 33.75 秒，而 SAMtools 耗时 48.86 秒。
D3 的全部记录均使用快速 SAM 解析器，因此较小的收益不是由解析器回退引起的。
该结果表明，并行转换的收益同时取决于转换方向和输入数据集。

这些应用表明，公共流水线能够以较低的实测运行时间支持不同的流式工作负载。
标志统计使用 BAM 读流水线，过滤连接 BAM 读取和写入，而两项转换连接相应的 BAM 和 SAM 流水线。
应用特定算子复用相同的批次调度和输出组件。
因此，这些结果将库基准测试扩展到完整的流式操作，而无需单独实现其基本处理阶段。

#### 3.3.2 分布式 BAM 处理

我们评估四项需要记录重排、分组或跨记录状态的分布式应用。
这些应用是归组、配对信息修正、坐标排序和重复标记。
SWBAM 在六个节点上使用六个活跃核组，SAMtools 使用针对每个应用和数据集选定的线程设置。
归组使用 66 个桶，fixmate 生成配对得分标签，BAM 输出使用压缩级别 1。
每个应用接收所需的已准备输入；输入准备不计入其独立运行时间。
表 5 汇总概述所述计时和存储条件下的三次运行时间中位数。

| D1 | Fixmate | 75.58 | **36.19** | 2.09 | 96 |
| D1 | 坐标排序 | 165.47 | **50.93** | 3.25 | 24 |
| D1 | 重复标记 | 139.54 | **49.13** | 2.84 | 127 |
| D2 | Collate | 406.73 | **138.68** | 2.93 | 127 |

SWBAM 的归组和排序使用其内存路径，SAMtools 排序在内存中进行。
SAMtools 归组使用临时文件。
存储和计时条件遵循概述。

归组和坐标排序受益于将重排工作分布到各 rank。
归组实现的运行时间比值为 2.72–2.93 倍，而坐标排序为 3.25–4.43 倍。
SWBAM 通过 CPE 读流水线提取记录元数据，在 MPE 上执行本地排序和 MPI 重分布，然后在压缩前归并或排序接收记录。
划分键有所不同：归组按 QNAME 对记录分组，而排序建立全局坐标顺序。
因此，这些应用将并行 BGZF 处理与分布式排序结合，而不只是依赖输入输出流水线。

尽管存在 QNAME 组依赖，fixmate 仍提供一致的改进。
其在 D1–D3 上的运行时间比值分别为 2.09 倍、2.09 倍和 2.02 倍。
MPE 处理完整的本地组，并交换跨越 rank 边界的组片段。
CPE 内核执行批次更新规划和记录重写，随后使用公共 BAM 写流水线。
这种组织方式避免重分布所有记录，同时保留配对字段和标签更新所需的分组。

重复标记表现出更强的数据集依赖，因为判定跨越记录、批次和 rank 边界。
运行时间比值从 D1 上的 2.84 倍降至 D2 上的 1.82 倍和 D3 上的 1.28 倍。
与逐记录过滤器不同，重复标记维护活跃候选，并延迟判定，直到相关的本地和远端信息可用。
D3 的运行触发边界回退路径，该路径维护增量边界状态，并延后处理未决记录。
这引入了公共解压和压缩内核之外的状态管理和协调工作。
D3 的最终输出保留 165,373,770 条记录，并包含 33,171,753 个重复标志，与 SAMtools 的总数一致。

外部有序段增加了处理开销，但在 D2 上保留了运行时间优势（表 6）。
SWBAM 将归组和排序限制为每个 rank 使用 8 GiB 算法工作区，在六个 rank 上分别生成 18 和 30 个有序段。
对应的处理时间为 157.35 和 149.97 秒，相对于内存路径结果分别增加 13.5% 和 30.7%。
有序段存储、交换和多路归并增加了排序过程的工作量。
归组的运行时间比值仍为 2.79 倍，排序为 3.47 倍。
这些测量包括概述所述存储条件下实际进行的基于 RAM 的临时数据读写；它们并未测量物理 SSD 上的外排性能。

**表 6：使用外部有序段时 D2 的运行时间比较**

| 应用 | SAMtools | SWBAM | 比值 | `-@` |
| --- | ---: | ---: | ---: | ---: |
| Collate | 439.30 | **157.35** | 2.79 | 127 |
| 坐标排序 | 520.79 | **149.97** | 3.47 | 96 |

表注：时间为三次运行的中位数，单位为秒，比值定义与表 5 相同。

SAMtools sort 使用总计名义容量为 48 GiB 的记录内存区，并生成两个有序段。
SAMtools collate 没有对应的 `-m` 内存设置。
临时和最终输入输出遵循概述中的存储条件。

### 3.4 去重流程性能

我们评估完整的四阶段流程，以确定应用级收益是否在顺序执行中得到保留。
每轮依次运行 collate、带配对得分计算的 fixmate、坐标排序和 markdup。
每个阶段的输出保存为完整的 BAM 文件，并由下一条命令使用。
SWBAM 在每个阶段使用六个活跃核组，而 SAMtools 使用选定的各阶段线程设置。
我们将每轮四个阶段的实测时间相加，并报告三个合计值的中位数，而不是独立阶段中位数之和。
这些实验使用四条独立命令，而不是融合的内存流程。

**表 7：四阶段去重流程的运行时间比较**

| 数据集 | 排序模式 | SAMtools | SWBAM | 比值 |
| --- | --- | ---: | ---: | ---: |
| D1 | 内排 | 597.46 | **195.96** | 3.05 |
| D2 | 内排 | 1380.03 | **505.12** | 2.73 |
| D3 | 内排 | 585.49 | **240.18** | 2.44 |
| D2 | 外排 | 1316.23 | **555.97** | 2.37 |

表注：时间为三个逐轮合计值的中位数，单位为秒。
SAMtools 合计值为四条命令的墙钟时间之和；SWBAM 合计值为概述中定义的四个处理区间之和。
比值在四舍五入前对这些中位数作除法得到。
排序模式指坐标排序；SAMtools collate 在两种情况下均使用临时文件。
外部有序段设置遵循表 6。
准备、Finalize 后保存和验证仍在 SWBAM 处理区间之外；这不是从启动器到退出的墙钟时间比较。

SWBAM 在三个数据集上均保留流程级运行时间优势（表 7）。
在内存排序下，其在 D1–D3 上的总处理时间分别为 195.96、505.12 和 240.18 秒。
对应的 SAMtools 合计值为 597.46、1380.03 和 585.49 秒，得到的比值为 3.05 倍、2.73 倍和 2.44 倍。
每个阶段仍然解码其输入，并生成完整的压缩输出。
因此，在不移除中间 BAM 文件，也不将四个应用替换为单个专用内核的情况下，这些收益仍然存在。

重复标记的贡献在三个工作负载间逐渐增加，并限制了整体收益。
在产生 SWBAM 总时间中位数的那一轮中，markdup 在 D1 上占处理时间的 25.1%，在 D2 上占 32.8%，在 D3 上占 43.1%。
这些比例使用该轮的四个实测阶段时间，而不是独立选取的中位数。
如上所述，除 BGZF 处理外，重复标记还需要候选状态维护和跨 rank 判定。
这一更大的有状态组件有助于解释，为什么流程比值低于单项排序的最大比值。

外部有序段增加了 SWBAM 的 D2 流程时间，但相对于所测 SAMtools 配置仍保留优势。
由于归组和排序增加了有序段存储和归并，总时间从 505.12 秒增至 555.97 秒，增加了 10.1%。
SAMtools 合计值为 1316.23 秒，得到的运行时间比值为 2.37 倍。
SAMtools 在这种情况下使用 96 个排序线程，而在内存排序情况下使用 24 个，因此其较低的外存情况合计值并不能证明仅外排本身就会减少运行时间。
SWBAM 临时文件读写在概述所述的基于 RAM 的存储条件下计入。

完整输出回读确认每轮 SWBAM 流程中的预期记录数和坐标顺序。
最终的重复标志数在 D1 上为 50,084,605，在 D2 上为 8,894,488，在 D3 上为 33,171,753。
D2 外部有序段流程生成的记录总数和重复标志总数与对应的内存排序流程相同。
这些检查确认了计数和顺序的一致性，而不是每个记录字段或重复标记分配在工具之间的完全一致性。
验证不计入报告的时间。
